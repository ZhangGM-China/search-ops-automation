# 拾心智能运营平台 — 设计参考
> 面向发现、诊断、治理、验证与追踪的数据密集型运营后台

**主题：** 浅色；桌面端优先，移动端使用同一视觉语言重组交互。

本规范记录当前 AIOPS 前端已经实现的视觉基线，供产品、设计和 AI 开发时对齐。它不引入第二套设计系统，也不将营销官网、品牌宣传页或未来设想当作当前实现。

权威实现来源是 frontend/src/styles/index.css 和 frontend/src/app/theme.ts；页面结构、响应式和组件使用规则以 FESpec.md 为准。

## Token — 字体

### 系统无衬线字体

字体栈为 -apple-system、BlinkMacSystemFont、Segoe UI、Roboto、Helvetica Neue、Arial、Noto Sans、sans-serif。当前项目没有引入 Roobert、Inter 或其他外部 Web 字体；新增页面不得自行加载字体。

- **字重：** 常规正文 400；交互和标签常用 500；页面标题或关键名称可使用 600–700。
- **技术字段：** 节点名、代码、ID 或 JSON 片段可使用现有等宽字体栈，避免技术值与普通文案混淆。
- **中文优先：** 中文页面不依赖英文展示字体或负字间距来建立层级，主要通过字号、字重、间距和语义颜色区分层级。

### 字号层级

| 角色 | 当前基线 | 典型位置 |
| --- | --- | --- |
| 页面标题 | 20px / 1.25 / 约 650 | .ops-page-title、详情页和工作台主标题 |
| 登录标题 | 26px / 1.2 | 登录页的产品名称 |
| 区块标题 | 14–16px / 600–700 | 配置分组、Card 标题、关键面板标题 |
| 正文与导航 | 14px / 400–600 | 表单、菜单、按钮、一般正文 |
| 表格表头与单元格 | 13px | 高密度数据表格 |
| 页面说明 | 13px / 1.55 | .ops-page-desc、说明与补充语 |
| 辅助信息与 Tag | 12px | 时间、来源、状态、弱化说明 |

## Token — 间距与形状

**基础取向：** 高密度运营后台。优先保证查询、数据、状态和动作在常见桌面宽度下可读、可点、可比较，而不是为装饰留出大面积空白。

### 间距层级

| 名称 | 值 | 当前用途 |
| --- | --- | --- |
| 页面边距 | 16px（移动端 12px） | --space-page；主内容区内边距 |
| Card 内容边距 | 14px（移动端 12px） | --space-card；小型 Card 与移动端 Card 内容 |
| 紧凑间距 | 8px | 标签、按钮、字段内元素、局部反馈 |
| 常规间距 | 12px | 表单项、卡片组、面板内部区块 |
| 分区间距 | 14–16px | 筛选区、工具栏、桌面双栏与模块区隔 |
| 页面级留白 | 按页面职责决定 | 不强制营销页的 96px 固定区块间距 |

### 圆角

| 元素 | 值 | 说明 |
| --- | --- | --- |
| 小控件、Tag、局部容器 | 6px | --radius-sm |
| Card、Modal、Drawer、一般容器 | 8px | --radius-md；后台默认圆角 |
| 顶部配置导航与局部工具栏 | 10px | 当前已有的强调容器，不作为全局默认 |
| 圆形头像或悬浮助理入口 | 50% 或组件自身规则 | 仅用于确有圆形语义的元素 |

### 阴影

| 名称 | 值 | 用途 |
| --- | --- | --- |
| 常规表面阴影 | 0 1px 2px rgba(15, 23, 42, 0.04) | Card、移动端 Card 与普通浮层 |
| 抬升阴影 | 0 8px 20px rgba(15, 23, 42, 0.06) | 少量需要突出层级的容器 |
| 下拉菜单阴影 | 0 14px 34px rgba(15, 23, 42, 0.14) | 顶部导航的下拉菜单 |

阴影只用于表达层级，不能替代边框、留白和内容分组。普通 Card 以浅边框和轻阴影为主。

### 布局

- 桌面端内容区由固定高度 62px 的顶部导航和可滚动内容区组成。
- 内容内边距为 --space-page；页面使用 .ops-page，通用容器优先使用 .ops-surface、.ops-subtle-box 与 .ops-clickable。
- 常规列表页遵循“标题与说明 → 筛选区 → 工具栏 → 表格 / 卡片 → 分页、空态或错误态”的顺序。
- 工作台、品牌详情与智能助理可以采用多栏或抽屉式布局，但不应把多个同等重量的 Card 无层级堆叠。
- 宽表格在移动端必须收敛为卡片列表、Popup 或抽屉交互，不能依赖横向滚动完成核心操作。

## 组件

### 主要业务操作按钮
**用途：** 查询、保存、确认、执行已审批的治理动作等当前页面的最高优先级操作。

使用 Ant Design primary Button 与 #1d4ed8 主色，当前主题不使用默认主按钮阴影。一个区域可以有一个明确的主操作，但受控写操作必须继续满足权限、预览、人工确认和回读要求；视觉强调不等于授权执行。

### 次级、危险与禁用按钮
**用途：** 重置、取消、返回、回滚、停止、删除或不可用操作。

次级操作使用默认或文本按钮，与主操作拉开层级。危险、回滚和高风险操作使用 Ant Design 的 danger 语义，并配合确认弹窗或明确状态说明；禁用状态必须保留文字与不可操作反馈，不能只降低透明度。

### 顶部导航
**用途：** 已登录桌面端的全局导航、产品身份和账号入口。

顶部导航为 62px 高的半透明白色表面，使用 1px 底边框和轻量 backdrop blur。左侧显示“拾心 · 智能运营”及“智能发现 · 智能诊断 · 智能治理”，中间为按权限过滤的功能导航，右侧为账号菜单。当前项与 hover 使用浅蓝底 #eef6ff 和主色 #1d4ed8。

### 页面标题与说明
**用途：** 列表、日志、配置和工作台页面的稳定信息层级。

使用 .ops-page-title 和 .ops-page-desc：标题表达当前页面名称，解释性文案放在说明中。不要在同类页面混用裸 h1/h2、临时 Typography 标题和随意字号。

### 筛选区与工具栏
**用途：** 日志、列表、治理记录与配置检索。

桌面端使用 Card size="small"、Form layout="inline" 和 .ops-filter-card；控件优先使用小尺寸，并保留换行后的行间距。查询、重置、导出与批量操作按重要性排列；移动端将筛选收纳到 Popup 或抽屉。

### 数据表格
**用途：** 运营日志、治理动作、实验记录、配置版本和可审计明细。

表格置于 Card 或 .ops-surface 内。表头和单元格为 13px，表头有弱化底色，数值与时间保持可比性；列过多时优先收敛非关键字段。状态、风险和执行结果使用 Tag 或 Alert 明确显示，不让用户从颜色或图标猜测含义。

### 状态标签与提示
**用途：** 治理状态、风险等级、数据质量、只读限制、执行结果和外部依赖异常。

Tag 表示稳定、紧凑的状态；Alert 表示需要用户理解或处理的异常、阻断和说明。每一个状态都要有中文文字标签，并按成功、警告、错误、信息选择语义色；不要将多种业务状态都压成蓝色。

### Card 与工作台面板
**用途：** KPI、趋势、任务摘要、配置分组、实验报告、诊断和审计信息。

使用白色表面、浅边框、8px 圆角和轻阴影。Card 可以承载一个清晰对象或一个清晰工作区；页面大区块不应形成无意义的 Card 套 Card。需要较低视觉权重的说明、摘要或辅助数据使用 .ops-subtle-box。

### Drawer、Modal 与确认链路
**用途：** 详情查看、模型/配置编辑、证据查看、动作预览和人工确认。

Drawer 和 Modal 与普通容器保持 8px 圆角和一致边框。动作确认页必须展示目标、影响范围、风险、当前状态和取消入口；高风险写入不得仅依赖一个醒目的按钮触发。

Query 治理执行详情弹窗统一采用固定尺寸和“结论优先”的信息顺序：结论置于内容顶部，并使用弱化表面底色、轻边框和内边距突出关键信息，标题与正文之间不使用分割线；连续指标使用一个整体外框，多行之间无留白，每个指标的标题与内容上下排列并以分割线区分；标题行使用弱化表面底色和 `#333333` 深色文字。重排序指标保持四等分网格，不因某一行只有两个指标而拉伸为二等分。治理策略、商品列表、执行结果、错误原因等非指标内容作为独立区块直接进入内容流，不再套用指标表单外框；独立区块标题沿用较大、深色的区块标题样式。重排序商品列表弹窗应垂直居中，策略固定在商品列表上方，商品列表单独滚动。

相关性详情的指标行按两行展示：第一行四等分显示“AI 检测、历史复用、正确商品、错误商品”，第二行显示“准确率、耗时、Token”；召回和重排序详情同样显示节点耗时与 Token。商品列表按“错误商品、正确商品”排序，使需要关注的问题商品优先出现。

重排序结论按低召回豁免、CTR 告警、CVR 告警、CTR/CVR 双告警和指标正常五类固定生成；告警结论追加 AI 重排序策略生成状态与重排序执行状态，两个状态独立展示，允许表达“策略已生成，但重排序执行失败”或“策略生成失败，重排序未执行”等组合。

### 空态、加载态与错误态
**用途：** 数据尚未生成、查询无结果、请求进行中或接口失败。

优先使用现有的 Empty、Skeleton、Spin 与 Alert，并使状态出现在对应内容区域。不能用留白、静默失败或“空白 Card”代替加载、空态和错误说明。

### 智能助理入口
**用途：** 从品牌详情或工作台进入智能运营助理。

当前支持卡通悬浮召唤与侧边按钮两种配置方式。吉祥物仅属于该可配置入口，不作为每个页面或每个区块的装饰元素；任何助理建议仍需经过现有的准备、确认或取消链路。

## 应做与不应做

### 应做

- 优先复用现有 CSS Token、Ant Design 主题和 .ops-* 通用 class，而非新建独立视觉体系。
- 用成功、警告、错误、信息等语义色表达业务状态，并同时展示清晰的中文状态文字。
- 保持筛选、表格、详情、抽屉、配置表单和移动端卡片之间的密度与层级一致。
- 在普通桌面宽度和移动端均保证关键操作可达、文字不重叠、页面无无意义横向滚动。
- 将受控写操作与普通阅读操作明显区分，并保留权限、风险、确认和结果反馈。
- 新增图表时使用克制的多色语义映射、Tooltip 和响应式容器；不能把图表的颜色变成没有解释的装饰。

### 不应做

- 不要引入 Roobert、Inter、Tailwind 或与现有 Token 平行的第二套设计系统。
- 不要把“开始试用”、合作伙伴 Logo、用户评价、星级评分、Newsletter、营销 Hero 等官网元素复制到运营后台。
- 不要规定“一个页面只能有一种颜色”；AIOPS 需要同时清楚呈现通过、风险、失败、只读和信息状态。
- 不要把按钮全部做成胶囊形，或把每个页面的主要操作做成高饱和大 CTA。
- 不要以渐变、重阴影、吉祥物或产品截图替代数据层级、表单结构和状态反馈。
- 不要为视觉调整修改业务文案、接口字段、权限规则、动作确认链路或测试依赖入口。
- 不要在通用视觉上散落 raw hex、fontSize、padding 或 borderRadius；一次性布局例外应保持局部且可解释。

## 层次感

- **普通内容表面：** 使用主边框与常规表面阴影。
- **悬浮菜单与局部工具栏：** 通过较高阴影、边框和 z-index 表达覆盖关系，不以缩放或夸张 3D 效果表达。
- **顶部导航：** 通过半透明白底、底边框与 10px blur 保持滚动时的定位感。
- **当前项与可点击反馈：** 使用主色浅底、边框或轻阴影；键盘焦点必须有可见 outline。

## 图像与图标

品牌 Logo 出现在顶部导航和登录页，承担产品身份识别。运营页面中的产品图片、商品图和图表必须服务于 Query、商品、趋势或治理证据，不能作为装饰性 Hero。

图标优先使用项目已有的 @ant-design/icons；图标按钮必须具备 aria-label。智能助理的吉祥物是可选入口的一部分，不扩展为普遍的页面插画规则。

## 布局

桌面端采用“产品身份 + 权限导航 + 账号入口 + 可滚动业务内容”的应用壳，而不是居中营销落地页。顶部导航左侧为品牌，中心为功能入口，右侧为当前账号；内容区以 16px 内边距承载列表、工作台、详情和配置页面。

列表与日志页优先让筛选、主要操作和数据表可在首屏理解；品牌详情、任务诊断、实验与智能助理可以使用分栏、时间线、抽屉或局部固定工具栏，但必须保持主要任务、当前状态和下一步操作清晰。

移动端沿用相同 Token 和状态语义，通过 NavBar、TabBar、Popup、全屏弹层和卡片列表重排桌面内容；不缩小整张宽表强行塞进手机屏幕。

## Agent 提示词指南

AI 新增或调整前端页面时，先读取 FESpec.md、frontend/src/styles/index.css 和与该页面同 Feature 的现有实现。按以下方式描述需求，而不是引用营销网页模板：

1. **列表 / 日志页：** “使用 .ops-page；标题和说明使用 .ops-page-title / .ops-page-desc；筛选区使用 small Card + inline Form；表格置于 Card 内；状态使用带文字的 Tag；补齐 loading、empty、error 与移动端卡片列表。”

2. **运营工作台：** “以一个明确的当前任务为主视觉，KPI、趋势、任务列表和详情抽屉分区，复用 --app-bg、--surface-bg、--surface-border 和 --brand-primary；不要构造 Hero、营销 CTA 或用户评价。”

3. **受控动作面板：** “将只读事实、风险提示、动作预览、确认 / 取消和执行结果分层展示；高风险状态使用 warning / danger 与 Alert，确认按钮不等于绕过权限或回读链路。”

4. **配置页：** “按业务分组组织字段，使用轻边框和浅色背景，保存 / 重置操作位置稳定；桌面端三列或两列字段网格在窄屏降为单列。”

5. **移动端：** “保留同一状态色、字号和语义；将宽表改为卡片流或 Popup 筛选，不新增第二套移动端主题。”

## 状态呈现模式

状态信息遵循“文字优先、颜色辅助、证据可进入”的原则：

- 成功、警告、错误、信息和默认状态使用现有语义 Token 或组件语义。
- Tag 适合紧凑、稳定的状态；Alert 适合需要说明原因、影响或下一步的状态。
- 颜色不能是唯一信息载体：状态文本、必要的图标、数据时间和详情入口必须可见。
- 对治理、回滚、质量门禁、外部依赖与 AI 建议，优先展示当前状态、风险和限制，而不是用积极的蓝色或绿色暗示“已成功”。

## 快速开始

### CSS 自定义属性

新样式应优先引用现有变量，而不是复制数值：

~~~css
.example-panel {
  padding: var(--space-card);
  border: 1px solid var(--surface-border);
  border-radius: var(--radius-md);
  background: var(--surface-bg);
  box-shadow: var(--surface-shadow);
  color: var(--text-primary);
}

.example-panel--selected {
  border-color: var(--brand-primary);
  background: var(--brand-primary-soft);
}
~~~

### Ant Design 主题

项目实际使用 Ant Design ThemeConfig；新组件优先继承该主题，而不是引入 Tailwind v4 或新主题框架：

~~~ts
export const appTheme = {
  token: {
    colorPrimary: '#1d4ed8',
    colorSuccess: '#047857',
    colorWarning: '#b45309',
    colorError: '#dc2626',
    colorText: '#0f172a',
    colorBgLayout: '#f6f8fb',
    colorBgContainer: '#ffffff',
    colorBorder: '#e2e8f0',
    borderRadius: 8,
    fontSize: 14,
  },
};
~~~
