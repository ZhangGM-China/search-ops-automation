# 库存恢复表线上迁移契约

| 字段 | 日期 |
| --- | --- |

## 1. 范围与目标

`inventory_recovery_task` 是当前已改造后的库存恢复任务表，不作为“旧表”删除或重建。本契约定义将其迁移到新的 Query Governance 命名空间时的扩展式、可回滚流程。

目标表：`query_governance_inventory_task`   
巡检历史表：`query_governance_inventory_check`  
迁移控制表：`query_governance_inventory_migration`

目标表使用原表 `id` 作为 `legacy_id`，因此详情页、动作幂等和回滚期间的任务身份保持稳定。目标表不直接复用自增 ID，也不在首个发布中删除原表。

## 2. 字段映射

| 当前表 | 目标表 | 规则 |
| --- | --- | --- |
| `id` | `legacy_id` | 稳定映射，唯一；迁移游标按此字段断点续跑 |
| `created_at` | `created_at` | 原样保留 |
| `updated_at` | `updated_at` | 原样保留 |
| `brand` | `brand` | 原样保留；空值需在生产预检中阻断或业务确认 |
| `product_id` | `product_id` | 原样保留；不推断外部 FK |
| `product_name` | `product_name` | 原样保留 |
| `original_query` | `query_text` | 名称统一，值原样保留 |
| `last_check_stock` | `broken_rate_percent` | 当前语义是最近断码率百分比整数，不是库存件数 |
| `status` | `status` | 仅允许 `monitoring`、`recovered`、`auto_stopped`、`manually_stopped`；未知值阻断 |
| `last_action_request_id` | `last_action_request_id` | 原样保留 |
| `last_action_generation` | `last_action_generation` | 原样保留，默认 0 |

巡检历史表从迁移回填时记录一条 `legacy_backfill` 快照；迁移切换后由巡检任务写入每次检查结果。现有任务表只有最新快照，不能伪造切换前的逐轮历史。

## 3. 阶段与门禁

1. `prepare`：备份并只读盘点；创建目标表、索引和控制表，不改原表。
2. `backfill`：按 `legacy_id` 分批复制，记录游标；重复执行不重复插入。
3. `dual_write`：应用在同一事务内写原表和目标表；旧表仍是读源。
4. `target_read`：完成校验和影子读后，详情页、库存巡检、恢复动作切换到目标表。
5. `observe`：至少观察一个完整巡检周期，核验新增、更新、自动停止、恢复和手动停止。
6. `retire`：仅在观察窗口和回滚演练通过后停止旧表写入；旧表保留回滚窗口，不在首个版本 `DROP`。

任一阶段出现未知状态、行数不一致、关键字段校验失败、双写异常或动作回读不一致，保持旧表读源并暂停切换。

## 4. 校验

- 总行数一致。
- `brand + query_text + product_id` 业务集合一致。
- 状态分布、断码率、动作请求 ID/代次逐行抽样或哈希一致。
- 详情接口、库存巡检、自动恢复、手动恢复回归通过。
- 回填完成后再次执行校验；增量双写期间按更新时间窗口重复校验。

## 5. 回滚

迁移控制表的 `read_mode` 是唯一切读开关。回滚只将其切回 `legacy`，保留目标表和历史表数据；不删除、不覆盖原表。恢复后先完成差异校验，再决定是否继续双写或重新切换。

## 6. 授权边界

本地 SQLite 演练、迁移代码和测试不代表生产 schema migration、生产数据迁移、应用发布或业务验收。生产执行必须按生产发布指南单独审批，并先完成备份、恢复演练和只读预检。
