> 本页是所有内部变更接口的执行入口。它不扩大接口开放范围；外部调用方只读 05 及其 OpenAPI allowlist。业务字段以 06～11 的模块页为准，本页补充执行所需的权限、状态、幂等、权威回读和失败恢复。

## 1. 阅读规则

- 先在 `internal-api-inventory.md` 确认 method/path，再看本页对应行，最后阅读模块页的业务字段。
- 当前共有 60 条变更路由；每条都必须落在下表，未列出的前端历史 URL 不构成接口。
- HTTP API 没有统一对外的 `Idempotency-Key`。只有表中明确支持的请求身份才能使用；不要自行添加参数或自动重放写请求。
- 统一错误语义见[03 通用协议、错误与流式传输](03-通用协议与错误契约.md)。

## 2. 执行档位

| 档位 | 代码状态 | 执行规则 |
| --- | --- | --- |
| `G` | `integrated` | 通过 ActionGateway；服务端生成或校验稳定请求身份，执行前 claim，持久化 attempt/terminal fact，按权威回读确认。等价请求返回既有终态，语义冲突返回 `409`。 |
| `N` | `not_integrated` | 尚未接入统一网关；不得自动重放。超时、断连或结果不明时先读取真实状态，无法确认则转人工处理。 |
| `L` | `not_required` | 仅本地状态、会话、认证生命周期或文件生成；按资源状态/版本回读，`409` 先 GET。涉及外部写入时不适用此档位。 |
| `C` | `legacy_contract` | 保留现有状态机兼容语义；重复确认/取消返回既有终态，不发送第二次外部写。 |

代码事实源只有上表右列的四种 `gateway_status`。当前 60 条变更路由的数量为：`integrated=31`、`not_integrated=7`、`not_required=21`、`legacy_contract=1`；文档中的 `G/N/L/C` 只是便于阅读的简称。

### 2.1 `G` 的共同流程

1. 校验当前用户、真实对象归属、品牌范围和动作权限；不信任请求体中的品牌或权限。
2. 从 `requestId`、`idempotencyKey`、`externalRequestId` 或确定性业务事实得到稳定请求身份；同一身份的语义冲突拒绝执行。
3. 条件 claim 后执行；超时、断连或本地终态写入失败进入 `execution_unknown`，不得按成功处理。
4. 以权威数据库/外部动作状态回读收口；只有终态和回读均一致才返回成功。
5. 过期 owner 先 fence；旧 owner 不得覆盖新 owner。失败或回读不确定时按表中恢复动作处理。

### 2.2 非 `G` 的共同规则

- `N`：状态冲突返回 `409` 或业务错误；先 GET，再由人工决定是否重新提交。
- `L`：本地事务失败回滚；文件下载中断不能当作完整成功。
- `A`：登录失败不重试密码；登出、改密后以当前用户/Token 状态回读。
- `C`：只允许服务端根据动作快照执行；已终态不得再次写外部系统。

## 3. 全量变更路由契约

下表的“请求”只列实际支持的字段；`?` 表示可选。请求身份字段仅在档位 `G` 的实现中按具体处理函数生效。

| 方法/路径 | 请求 | 权限与状态前置 | 档位 |
| --- | --- | --- | --- |
| `POST /api/dashboard/no-result-governance/batches/{batch_id}/rollback` | `reason?`；可带请求身份 | 批次存在且品牌在授权范围；动作可回滚 | `G` |
| `POST /api/dashboard/no-result-governance/queries/{query_id}/rollback` | `reason?`；可带请求身份 | Query 存在且品牌在授权范围；动作可回滚 | `G` |

| `POST /api/dashboard/no-result-governance/queries/{query_id}/execution/start` | `reason?`；可带请求身份 | 执行权限；Query 品牌授权；不存在未收口外部写 | `G` |
| `POST /api/dashboard/no-result-governance/queries/{query_id}/execution/pause` | `reason?`；可带请求身份 | 执行权限；当前状态允许暂停 | `G` |
| `POST /api/dashboard/no-result-governance/queries/{query_id}/execution/resume` | `reason?`；可带请求身份 | 执行权限；当前状态允许恢复 | `G` |

### 3.5 断码与其他库存动作

| 方法/路径 | 请求 | 权限与状态前置 | 档位 |
| --- | --- | --- | --- |
| `POST /api/dashboard/actions/blacklist` | `brand,query,sku`；可带商品名、原因和请求身份 | 品牌和执行治理权限；目标商品可拉黑 | `G` |
| `POST /api/dashboard/actions/blacklist/batch` | `items[]`；每项包含 `brand,query,sku` | 品牌和执行治理权限；逐项执行拉黑和审计 | `G` |
| `POST /api/dashboard/actions/cancel-blacklist` | `brand,query,sku`；可带 `reason`（仅审计）、`correctionRule`（用户手填的相关性规则，与取消动作同一本地事务写入）和请求身份 | 品牌和治理权限；目标动作可撤销；`correctionRule` 为空返回 `400` | `G` |
| `POST /api/dashboard/actions/cancel-blacklist/batch` | `items[]`；每项包含 `brand,query,sku` | 品牌和治理权限；逐项执行目标动作 | `G` |
| `POST /api/dashboard/actions/cancel-demotion` | `brand,query,sku`；可带请求身份 | 品牌和治理权限；目标动作可撤销 | `G` |

拉黑/取消拉黑（含批量）信任上游写接口的业务成功结果（`code 0/200`）作为权威结论，不再发起 `product/list` 回读；超时、断连等传输结果未知时仍按 `G` 档位未知收口，禁止自动重放。库存降权等其他外部治理动作仍必须回读外部动作状态及请求标识，不能把请求已发送判定为成功。

## 4. 失败、回读与人工处理

| 情况 | 处理 |
| --- | --- |
| `400` | 请求字段、状态前置或业务条件无效；修正后重新提交。 |
| `401/403` | 重新取得合法身份或收敛权限；不重试业务写入。 |
| `404` | 先确认对象是否仍存在；不盲目创建替代对象。 |
| `409` | 先 GET 权威状态和版本；只在新状态允许时重新生成请求身份。 |
| 写请求超时、断连或回读不一致 | 按档位处理；`G` 进入未知/人工收口，`N` 禁止自动重放。 |
| 外部写入已发生但本地状态未知 | 保留 `externalRequestId`，先做权威回读或回滚；不能以 HTTP 请求已发送判定成功。 |
