# 02 认证授权与品牌隔离

| 字段 | 日期 |
| --- | --- |
| 创建时间 | 2026-07-23 |

> 本页定义 JWT、用户权限、品牌范围和受控写入的共同边界。页面可见性不能替代服务端数据和动作授权。

## 1. 认证接口索引

| 方法 | 路径 | 鉴权 | 请求 | 成功响应 |
| --- | --- | --- | --- | --- |
| POST | `/api/auth/login` | 匿名；仅受控管理端 | `username,password` | `access_token,token_type,user` |
| GET | `/api/auth/me` | Bearer；当前用户 | 无 | 当前用户对象 |
| POST | `/api/auth/logout` | Bearer；当前用户 | 无 | 当前用户全部会话撤销结果 |
| POST | `/api/auth/change-password` | Bearer；当前用户 | `oldPassword,newPassword` | 密码修改结果 |

### 1.1 `POST /api/auth/login`

#### 请求

```json
{"username": "<username>", "password": "<password>"}
```

#### 成功响应

返回 `access_token`、`token_type` 和 `user`。登录接口首期不对外开放。

#### 错误与重试

凭据不正确返回 `400`；不要自动重复提交密码。

#### 调用示例

```bash
curl --fail-with-body -X POST \
  'https://ops.example.test/api/auth/login' \
  -H 'Content-Type: application/json' \
  -d '{"username":"<username>","password":"<password>"}'
```

### 1.2 其他认证接口

- `GET /api/auth/me`：读取当前用户。
- `POST /api/auth/logout`：撤销当前用户全部会话。
- `POST /api/auth/change-password`：修改密码；安全字段变化后旧 Token 失效。

这些接口均需 Bearer，具体失败语义见[03 通用协议与错误契约](03-通用协议与错误契约.md)。

## 2. JWT 与会话

- 业务路由通过 `OAuth2PasswordBearer` 读取 `Authorization: Bearer <JWT>`。
- JWT 使用 HS256，源码当前有效期为 24 小时。
- 无 token、解码失败、用户不存在、账号停用或授权版本失效均返回 `401`；当前错误详情为 `Could not validate credentials`。
- Token 携带服务端 HMAC 授权版本。授权版本由密码哈希、账号 active 状态、角色、页面/品牌/动作权限和 `users.updated_at` 共同生成。
- 改密、重置密码、停用或权限变更会自然撤销旧 Token；撤销事实保存在用户表，不依赖单进程内存或 Redis。
- 认证审计只记录事件类别、结果和用户 ID，不记录用户名、密码、JWT 或请求 payload。

## 3. 权限模型

登录用户使用以下权限字段：

| 字段 | 作用 | 不能替代 |
| --- | --- | --- |
| `pagePermissions` | 页面可见性 | 数据安全和写入授权 |
| `brandPermissions` | 服务端数据品牌范围 | 动作权限 |
| `actionPermissions` | 高风险动作授权 | 品牌范围校验 |

- 业务读写必须以服务端 `brandPermissions` 为准，不信任前端传入的品牌范围。
- Top Query 按路径 `brand` 或任务所属品牌校验；No-Result、助理会话和动作按对象所属品牌再次校验。
- 多品牌用户调用助理时未指定 `brand` 返回 `400`；已有会话的品牌不可切换。

## 4. 角色与错误

源码可识别 `platform_admin`、`brand_admin`、`brand_member`：

- 平台管理员（前端显示为“超级管理员”）拥有全局页面、品牌和动作权限；页面与品牌权限按当前配置动态继承，新增模块或品牌无需逐项回填账号记录。
- 品牌管理员只能在所属品牌范围管理成员和被授予的配置能力。
- 外部调用方不要根据角色名推断完整权限，应按服务端返回的 `403` 处理。

## 5. 受控写入边界

页面可见、品牌范围和动作授权是三层独立判断。服务端在实际写入前必须重新读取真实对象归属、最新权限和动作状态。

助理 `prepare` 固化会话、动作、任务、品牌和 Query 的授权快照；`confirm` 前重新校验权限、对象归属、动作状态和有效期。写入请求的稳定身份、执行租约、权威回读和失败恢复见[04 内部写入与执行契约](04-内部写入与执行契约.md)。
