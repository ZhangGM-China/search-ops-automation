## 2. 请求契约

### 2.1 账号

| 接口 | 请求 body | 约束 |
| --- | --- | --- |
| `POST /api/admin/users` | `username`；`role?`、`pagePermissions?`、`brandPermissions?`、`actionPermissions?` | 用户名必须唯一；品牌管理员只能提交自身品牌范围；服务端生成临时密码。 |
| `PUT /api/admin/users/{user_id}` | `isActive?`、`role?`、`pagePermissions?`、`brandPermissions?`、`actionPermissions?` | 只更新提交的字段；非平台管理员不能提升角色或写入越权品牌。 |
| `POST /api/admin/users/{user_id}/reset-password` | 可选请求身份字段 | body 可为空；服务端生成临时密码，旧授权版本失效。 |
| `POST /api/admin/users/{user_id}/revoke-sessions` | 可选请求身份字段 | body 可为空；只撤销目标用户会话。 |
| `DELETE /api/admin/users/{user_id}` | 可选请求身份字段 | body 可为空；内置 `admin` 拒绝删除。 |

`role` 当前包括 `platform_admin`、`brand_admin`、`brand_member`；`pagePermissions` 只控制页面可见性，不能替代 `brandPermissions` 或 `actionPermissions`。

### 2.2 助理访问配置

> 该接口组仅为历史配置和回滚兼容保留，不再作为账号页的用户授权入口。智能助理运行时直接继承账号 `brandPermissions`，`userBindings` 不会覆盖或缩小账号品牌范围。

`POST /api/admin/assistant/access-config` 是受管理范围内的整体替换请求，body 必须同时包含以下三个数组；清空现有配置时还必须传 `confirmClear: true`：

| 字段 | 数组元素主要字段 |
| --- | --- |
| `brandSpaces` | `id?`,`brand`,`displayName`,`defaultAgentBindingId?`,`enabled` |
| `agentBindings` | `id?`,`brandSpaceId`,`displayName`,`modelDisplayName`,`modelName?`,`availableModels?`,`supportsModelSwitch?`,`bindingType`,`enabled` |
| `userBindings` | `id?`,`userId`,`brandSpaceId`,`agentBindingId?` |

引用 ID 必须是整数或十进制字符串，引用对象必须存在并在同一品牌空间；跨品牌引用返回 `403`，空集合未确认返回 `409`。

### 2.3 节点模型配置

| 接口 | 请求 body |
| --- | --- |
| `POST /api/admin/node-model-config/drafts` | `entries`（按节点键映射 `channel,primaryModel,fallbackModel`）；`changeNote?` |
| `POST /api/admin/node-model-config/versions/{version}/publish` | `expectedVersion?`；版本号在 path。 |
| `POST /api/admin/node-model-config/rollback` | `targetVersion`；`expectedVersion?`。 |

发布和回滚均使用当前 active version 做 CAS；版本冲突返回 `409`。节点字段校验和返回结构以当前配置服务为准。

### 2.4 页面配置中心

页面配置中心用于管理只影响前端展示的可选内容，不改变 Query 治理、品牌配置、知识图谱或其他底层业务状态。配置采用后端注册表驱动，前端按 `definitions` 中的分组和排序元数据渲染。definition 除稳定 key、作用域、默认值和展示元数据外，支持 `boolean` 与 `metric_list`；metric list 通过 `options`、`minItems`、`maxItems` 描述合法指标和边界。

`GET /api/admin/page-config` 返回：

- `schemaVersion`：页面配置 schema 版本；
- `version`：当前全局配置版本，缺失或非法版本按 `0` 处理；
- `values`：按注册 key 合并后的有效值；缺失字段使用定义中的 `defaultValue`；
- `definitions`：配置项的 `key`、`groupKey`、`groupLabel`、`label`、`description`、`type`、`scope`、`defaultValue` 和排序信息；metric list 另含候选项及其数量约束。

`POST /api/admin/page-config` 请求 body 为 `{ "expectedVersion": 0, "values": { "brand_overview.card.show_operational_data": false, "brand_overview.card.metrics": ["pass_rate", "pending_count"] } }`。`values` 支持部分更新；未知 key、类型不匹配、metric list 越界/重复/含未知选项和非法 `expectedVersion` 返回 `400`；版本不匹配返回 `409`。只有平台管理员可以修改，所有登录用户可以读取有效配置。保存经过 ActionGateway、审计、持久化和回读；缺失配置使用注册表默认值。

schemaVersion 当前为 `2`，配置 key 分为品牌总览数据看板、品牌卡片、运营数据，以及品牌详情的 Query 列表和 Query 详情。`brand_overview.show_global_metrics` 默认开启并控制数据看板整体展示，`brand_overview.global_metrics` 控制其中的指标和顺序；`brand_overview.card.primary_metric` 为单选指标列表，默认 `query_count`，控制品牌卡片右上角主指标；全局比率按合并后的分子、分母计算。全局与卡片辅助指标按实际项数平分一行，窄屏空间不足时仍保持一行，过长标签省略。运营数据的图表、表单开关仍以 `brand_overview.drawer.show_chart` 和 `brand_overview.drawer.show_table` 持久化，只在前端与转化率指标编辑器组合展示；Query 列表的 `brand_detail.query_card.show_metrics` 与 `brand_detail.query_card.metrics` 同理组合展示。运营数据容器在品牌卡片运营数据开关关闭时不渲染，但不会丢弃其已保存的指标值。v1 已存配置在读取时迁移旧运营数据/昨日数据开关、卡片主指标及三个卡片辅助指标；保存后以 v2 key 持久化，乐观版本号和 ActionGateway 语义不变。

### 2.5 系统配置

`POST /api/admin/config` 接受 `safety_config?` 和 `brand_configs?`。平台管理员可更新安全配置和所有品牌；品牌管理员只能更新自身品牌中允许编辑的字段。未知或未授权字段被忽略或拒绝，不得把前端完整对象当成可写 schema。

### 2.5 运营日志与库存

| 接口 | 请求 |
| --- | --- |
| `GET /api/dashboard/blacklist-logs`、`GET /api/dashboard/demoted-logs` | Query：`date?`、`brand?`、`search?`、`page?`（默认 1）和 `limit?`（默认 20，最大 100）。无权品牌返回空集合，不等于授权成功。 |
| `GET /api/dashboard/stock-tasks` | Query：`brand?`、`status?`、`search?`、`page?`（默认 1）和 `limit?`（默认 20，最大 100）。 |
| `POST /api/dashboard/stock-tasks/{task_id}/toggle-status` | `status` 必须为 `monitoring` 或 `manually_stopped`；可选 `idempotencyKey`。 |
| `POST /api/dashboard/actions/blacklist` | `brand`、`query`、`sku` 必填；`productName?`、`reason?` 和请求身份字段可选。 |
| `POST /api/dashboard/actions/blacklist/batch` | `items` 必须为非空数组；每项包含 `brand`、`query`、`sku`，逐项执行权限检查、审计和权威回读。 |
| `POST /api/dashboard/actions/cancel-blacklist` | `brand`、`query`、`sku` 必填；`reason?`、`correctionRule?` 与请求身份字段可选。`reason` 只写取消理由审计记录，不写入相关性规则。`correctionRule` 仅由纠正弹窗“纠正并取消拉黑”提交，与取消动作在同一受控请求中原子写入相关性规则；传入空字符串或纯空白返回 `400`。 |
| `POST /api/dashboard/actions/cancel-blacklist/batch` | `items` 必须为非空数组；每项包含 `brand`、`query`、`sku`，逐项执行权限检查、审计和权威回读。批量入口不写相关性规则。 |
| `POST /api/dashboard/actions/cancel-demotion` | `brand`、`query`、`sku` 必填；可选请求身份字段。 |

拉黑、取消拉黑和取消降桶会先验证品牌和治理策略并执行权威回读；当前无法提供权威外部回读的品牌返回 `409`，不得把请求发送成功当成治理成功。

## 3. 响应、错误与执行

- 当前没有统一成功 envelope；账号、配置和日志接口分别返回对象、列表或 `{items,total}`。
- 认证、品牌和动作权限规则见 [02 认证授权与品牌隔离](02-认证授权与品牌隔离.md)。
- 通用 HTTP 错误、分页、日期和 JSON 规则见 [03 通用协议、错误与流式传输](03-通用协议与错误契约.md)。
- 每个变更接口的执行档位、稳定请求身份、状态前置、权威回读、`409`、超时和未知结果处理见 [04 内部写入与执行契约](04-内部写入与执行契约.md)。客户端不得根据本页索引自行重放写请求。
