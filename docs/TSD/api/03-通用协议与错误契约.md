## 1. 请求基础

| 项目 | 约定 |
| --- | --- |
| Base URL | 生产为 `https://ops.example.test/api`；本地前端使用 `/api`。 |
| JSON body | 写请求使用 `Content-Type: application/json`。 |
| GET 参数 | 使用 query string；未在对应接口页声明的参数不得自行添加。 |
| 鉴权 | 健康检查和登录除外，通常使用 `Authorization: Bearer <JWT>`。 |
| 路径参数 | 按接口页声明的类型传递；不要把展示名称当作 ID。 |
| 扩展字段 | 消费方忽略未列出的响应字段，不把当前处理函数的全部返回值当成长期契约。 |

## 2. 成功响应

当前没有全局统一的成功 envelope；接口按业务返回以下形态：

| 形态 | 示例 | 适用场景 |
| --- | --- | --- |
| 列表 | `{ "items": [], "total": 0 }` | 分页或完整集合 |
| 聚合对象 | `{ "brands": [] }` 或 `{ "brand": "..." }` | 总览、摘要和趋势 |
| 详情对象 | 直接返回业务对象或稳定顶层字段 | 任务、实验和状态读取 |
| 文件响应 | 二进制 body + `Content-Disposition` | 实验导出 |

机器可读的外部只读与外部计算响应以 [`openapi.json`](openapi.json) 为准；内部接口暂以对应专题页、当前处理函数和前端调用共同核对。

## 3. 错误契约

常见 JSON 错误为：

```json
{"detail": "..."}
```

验证错误可能是 FastAPI 字段级结构；当前没有稳定业务 `code`，调用方不得从 `detail` 文本解析业务码。

| HTTP | 语义 | 调用方处理 |
| --- | --- | --- |
| `400` | 参数、状态或业务前置条件无效 | 修正请求后再提交。 |
| `401` | Bearer 缺失、失效或授权版本过期 | 重新取得身份后最多重试一次。 |
| `403` | 角色、品牌或动作权限不足 | 不重试，收敛权限范围。 |
| `404` | 资源不存在 | 先确认资源生命周期，不盲目创建替代资源。 |
| `409` | 版本、并发或状态冲突 | 先 GET 权威状态；写入恢复按 04 执行。 |
| `422` | 请求结构或字段类型未通过校验 | 按返回的字段错误修正请求。 |
| `429` | 部署层限流（若启用） | 仅按 `Retry-After` 或有限退避处理。 |
| `5xx` | 服务或依赖故障 | GET 可有限退避；写请求按 04 进入未知结果处理。 |

GET 的有限重试只适用于连接失败、超时和 `5xx` 等暂时性故障；`400/401/403/404/409` 不因重试而改变语义。健康探针也不能触发治理写入。

## 4. 分页、过滤与日期

- 只有路由签名实际声明的参数才可用；未声明的 `page/pageSize` 不应假设生效。
- Top Query 任务和 Query 列表当前返回完整 `items + total`，不接受分页参数。
- No-Result 列表使用 `page`（默认 1）和 `limit`（默认 20，最大 100），返回 `items + total`。
- 实验列表和实验 Query 列表使用 `page`（默认 1）和 `pageSize`（默认 20，最大 100）。
- 日期参数按接口签名使用 `YYYY-MM-DD`；不传日期时通常读取最新数据，不能当成固定快照。

## 5. SSE 流式传输

### 5.1 适用接口

- `POST /api/assistant/chat/stream`

两者均使用 JSON 请求、Bearer 鉴权，响应 `Content-Type: text/event-stream`。每个事件是一个 SSE `data` 帧，内容为 JSON：

```text
data: {"type":"delta","content":"..."}

```

### 5.2 事件类型

| `type` | 稳定字段 | 说明 |
| --- | --- | --- |
| `delta` | `content` | 增量文本。 |
| `tool_call` | `id,name,arguments` | 助理工具调用。 |
| `tool_result` | `toolName,summary` | 助理工具结果摘要。 |
| `error` | `content` | 连接建立后的运行错误。 |
| `done` | `sessionId,proposedActions,toolResults,runtime` 或 Ops 状态字段 | 正常结束；助理服务在此事件后持久化会话。 |

HTTP `200` 只表示流已建立；建立后仍可能收到 `error` 事件。客户端必须同时处理 HTTP 错误和事件错误，收到 `done` 或 `error` 后关闭连接。断线不得自动重放 POST；用户明确重试助理会话时才传 `retryOfMessageId`。

## 6. 最小调用示例

```bash
curl --fail-with-body \
  'https://ops.example.test/api/dashboard/top-query/overview' \
  -H 'Authorization: Bearer <issued-jwt>'
```

```bash
curl --no-buffer --fail-with-body -N -X POST \
  'https://ops.example.test/api/assistant/chat/stream' \
  -H 'Authorization: Bearer <issued-jwt>' \
  -H 'Content-Type: application/json' \
  -d '{"message":"<question>","brand":"atlas"}'
```
