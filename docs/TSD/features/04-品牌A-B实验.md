## 1. 模块定位与边界

品牌 A/B 实验是 Query 治理的实验扩展，用固定样本比较治理组与对照组的变化。

- 它复用 Top Query 任务、动作和验证能力，不重定义 Query 治理主流程、全局权限或受控写入规则。
- 每个运行中实验固定 20 个实验组 Query 与 20 个对照组 Query：实验组持续治理，对照组只观测。
- 它输出运营效果信号，不支持严格因果归因；随机分流、全量品牌指标治理和非 Top Query 实验不属于本模块。

## 2. 上下文与协作关系

```text
Top Query 任务与日数据
-> 固定实验样本和基线
-> 实验组治理 / 对照组只读观测
-> 质量门禁与效果计算
-> 报告、导出与配置工作台
```

- 实验通过新的确定性 Query 治理工作流参与品牌日编排；不会另起一条 Top Query 执行主链，也不依赖旧 Agent Loop。
- 它依赖 Top Query 的任务、动作和快照事实，并向配置工作台提供实验生命周期、质量、效果和导出视图。
- schema、接口、调度和运行事实分别以[数据存储设计](../03-数据存储设计.md)、[接口设计](../04-接口设计.md)、[调度与中间件](../06-调度与中间件.md)、[运行、恢复与发布边界](../07-兼容性灰度与运维.md)为准。

## 3. 方案概览

| 组件 | 设计职责 |
| --- | --- |
| Query 身份层 | 区分展示 Query 与实际治理身份，阻止等价 Query 跨组重复。 |
| 实验生命周期服务 | 管理样本、排期、基线冻结、每日快照、质量和污染审计。 |
| Top Query 编排 | 仅为实验组创建和执行任务，复用既有治理工作流。 |
| 分析与报告服务 | 汇总真实分子/分母、质量证据、效果、趋势和 Query 贡献。 |
| 配置工作台与导出 | 提供样本配置、只读效果页和基于后端权威结果的导出。 |

## 4. 核心流程与状态

1. 实验按 `draft -> scheduled -> running -> ended` 演进；`draft/scheduled` 可取消，`running` 只能按结束流程收口。
2. 排期后样本和日期锁定。计划开始日必须完整取得 40 个 Query 的 7 日基线和首日观测，再原子切换为 `running`、冻结基线、写入首日快照并创建 20 个实验组任务。
3. 每日按“抽取锁定 20+20 → 校验身份和样本形状 → 写入快照 → 执行 20 个实验组任务 → 回写动作证据 → 扫描对照污染 → 收口指标”推进。
4. 同日重跑复用锁定基线、当日快照和 20 个实验组任务；跨日创建新日任务。已收敛任务不得再次调用治理工作流或外部动作。

## 5. 关键技术决策与不变量

- 展示值使用 `query_text`，归并使用 `normalize_query_key()`，真实治理对象使用 `normalize_governance_query_key()`；后端始终是跨组重复校验权威。
- 固定 20+20 样本和治理前 7 日 Search UV 加权基线，避免每日 Top-N 波动改变实验对象。
- 效果按真实分子/分母聚合，净效果为实验组变化减去对照组变化；不能平均每日比例或用 PV 代替 Search UV 分母。
- 当前只支持 `top-query-ab-test-v2`；旧版本记录不能进入激活、运行或报告读取链，必须通过专门迁移处理。
- 对照组永不治理是硬约束，不能因为其他入口、重试或人工动作被绕过。

## 6. 异常、安全与质量边界

- 正常日必须满足 40/40 可观测、20/20 实验组任务完成、对照组零任务/零动作/零污染，且没有 failed 或 unresolved 的任务和动作。
- 数据不完整、样本错配、对照污染、任务失败或人工待处理时，质量必须失败：不以 0 补指标、不输出正式效果结论、不自动结束实验。
- 对照组写保护位于服务层，覆盖任务、动作审批/执行、恢复、调度、助理、无结果词治理和底层业务入口；API 预校验不是唯一防线。
- 报告和导出只消费后端权威 DTO；导出使用绑定实验的签名快照，不以导出时的实时数据重新计算效果。
