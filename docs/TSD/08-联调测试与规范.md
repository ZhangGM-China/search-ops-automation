# 08 联调验证与证据边界

| 字段 | 日期 |
| --- | --- |
| 创建时间 | 2026-07-23 |
| 最后更新时间 | 2026-08-19 |

## 1. 文档目的

本文定义联调范围、验证证据层级和事实来源，用于帮助人和 AI 判断“一项变更需要验证什么”以及“当前证据能证明什么”。

本文不保存某次测试或发布的通过状态；只保留稳定的测试入口和证据边界。脚本实现、测试收集范围和具体模块测试以当前代码为准。

## 2. 联调范围

| 联调面 | 需要确认的边界 |
| --- | --- |
| 前端与后端 API | 路由、认证、品牌隔离、请求/响应契约和错误语义一致。 |
| 业务模块与调度 | 任务注册条件、状态流转、幂等、恢复和终态收口一致。 |
| 生产只读数据源 | Top Query / No Result 的连接、查询口径、字段和数据新鲜度满足业务要求。 |
| 外部受控写系统 | 权限、人工确认、稳定请求身份、权威回读、未知结果和回滚边界正确。 |
| 模型与外部 Gateway | 配置、超时、降级、脱敏和失败收口正确，且不绕过本地确定性逻辑。 |
| 应用运行与发布 | API、Scheduler、数据库、应用版本和客户流量的证据分层独立成立。 |

## 3. 验证证据层级

| 层级 | 能证明 | 不能替代 |
| --- | --- | --- |
| 静态检查 | 文档、契约、引用或代码结构在检查范围内一致。 | 代码实际执行。 |
| 自动化测试 | 指定 commit 和环境下的单元、集成或前端行为通过。 | 真实外部系统联调、发布或业务验收。 |
| 外部系统联调 | 指定环境中的真实连接、读写契约或回读链路成立。 | 应用已发布或客户流量已切换。 |
| Release Gate | 指定 release SHA 已通过发布前门禁。 | 生产 schema 迁移、生产发布或发布后验收。 |
| 生产发布验证 | 指定不可变 release 在目标环境的身份、运行和回滚证据成立。 | 客户入口已切换或业务效果达标。 |
| 业务验收 | 指定版本、环境、数据周期和验收人下的 PRD 验收结论。 | 后续版本或其他环境仍然通过。 |

任何“已验证”结论都必须绑定日期、commit/release SHA、环境、执行入口和结果。本文中的层级定义不是通过证据。

## 4. 测试入口与边界

| 场景 | 入口 | 能证明 | 不能替代 |
| --- | --- | --- | --- |
| 快速门禁 | `ENV=test bash scripts/ci/test_fast.sh` | 静态契约、项目卫生和本地测试工具入口可用。 | 全量测试、浏览器验证或外部系统联调。 |
| 后端 | `ENV=test OPENAI_API_KEY=test-key bash scripts/ci/test_backend.sh` | 隔离环境中的后端自动化测试、静态检查和覆盖率。 | 真实外部系统、发布或生产验收。 |
| 前端 | `ENV=test bash scripts/ci/test_frontend.sh` | Vitest、lint 和 TypeScript/Vite 构建。 | 浏览器链路、真实 API 或移动端页面验收。 |
| 浏览器 E2E | `ENV=test OPENAI_API_KEY=test-key bash scripts/ci/test_e2e.sh` | 临时 SQLite、API、Vite 和 Playwright 的本地全链路。 | 真实外部系统、发布或生产验收。 |
| 发布前门禁 | `ENV=test bash scripts/ci/test_release_gate.sh` | 指定 release SHA 的发布前只读检查和自动化门禁。 | 迁移、发布、流量切换或业务验收。 |

前端依赖安装、脚本参数、收集规则、失败码和辅助脚本以 `scripts/ci/`、`frontend/package.json` 与测试代码为事实源；不再维护独立的脚本资产清单或历史耗时基线。

## 7. 维护原则与 Change Map

- 修改功能时，先从本文定位联调面和证据层级，再到权威文档选择具体验证入口。
- 只有联调面、证据层级、PRD 映射或测试入口矩阵变化时才更新本文；不记录辅助脚本资产清单或历史耗时。
- 某次测试、发布或验收的状态写入对应交付证据，不回填到本文。
- 没有自动化验证时，在变更记录中明确说明已完成的静态/手工检查和未验证项，不使用模糊的“已验证”。
- 修改 PRD 验收项时，同步检查本文第 6 节映射；修改测试入口时，同步检查本文第 4 节及引用本文的文档。
