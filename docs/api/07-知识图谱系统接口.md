# 知识图谱系统接口

## 1. 全局配置

### 1.1 环境信息

|变量|值|
|---|---|
|`baseUrl`|`https://kg.example.test`|

### 1.2 鉴权方式

知识图谱系统接口通过 HTTP Header 中的 Bearer Token 鉴权。

通用 Header：

```http
authorization: Bearer <from-controlled-secret-provider>
content-type: application/json;charset=UTF-8
```

本文请求示例只保留占位符；实际 Token 必须在运行时从受控 secret provider 获取。

### 1.3 sceneId 获取方式

知识图谱的大部分标签、标签关系等增删改接口都需要传入 `sceneId`。

#### 1.3.1 ATLAS、HARBOR、Riviera、Lumen

ATLAS、HARBOR、Riviera、Lumen 的 `sceneId` 通过通用业务系统配置接口获取。

知识图谱没有独立的 STG 场景。无论 AIOPS 运行在 `test` 还是 `prod`，`sceneId` 都从正式业务系统配置地址读取；商品搜索等其他业务接口仍按当前环境选择 STG 或正式地址。

接口 URL：

`GET https://search.example.test/admin-api/config/new/word/get/cfg_kg_key`

鉴权要求：

- Header 中的 `Authorization` 和 `tenant-id` 参照 `docs/api/01-外部业务系统接口.md` 中对应品牌的 `apiKey` 与 `tenantId`。
- 示例请求使用 ATLAS 的 `apiKey` 与 `tenantId`。

请求示例：

```bash
curl -X GET "https://search.example.test/admin-api/config/new/word/get/cfg_kg_key" \
  -H "Authorization: Bearer <from-controlled-secret-provider>" \
  -H "tenant-id: 235" \
  -H "pragma: no-cache"
```

返回示例：

```json
{
  "code": 0,
  "data": "{\"bucket\":\"search-data\",\"tagKey\":\"kg_atlas/allTagFile\",\"relKey\":\"kg_atlas/allRelFile\",\"ossBrand\":\"searchops-atlas-search\",\"ossPrefix\":\"kg_atlas/\",\"sceneId\":\"1487491885693272064\"}",
  "msg": ""
}
```

返回字段说明：

|参数名|类型|说明|
|---|---|---|
|code|integer|状态码，`0` 表示成功|
|data|string|JSON 字符串，需解析后读取 `sceneId`|
|msg|string|响应消息|
|data.sceneId|string|知识图谱场景 ID|

#### 1.3.2 Summit、Meadow

Summit 与 Meadow 的 `sceneId` 使用固定值。

|品牌|sceneId|
|---|---|
|Summit|`1258129681140809728`|
|Meadow|`1445369145549258752`|

## 2. 标签接口

### 2.1 新增标签接口

#### 接口描述

新增知识图谱标签，并设置标签所属场景、维度、名称、权重、语言字段和扩展字段。

#### 接口 URL

`POST {baseUrl}/admin/tag/addTag`

#### 鉴权要求

```http
authorization: Bearer <from-controlled-secret-provider>
content-type: application/json;charset=UTF-8
```

#### 请求参数

|参数名|类型|是否必填|说明|
|---|---|---|---|
|params|object|是|业务参数对象|
|params.isEnglish|integer|是|是否英文标签，`0` 否，`1` 是|
|params.luansheng|string|否|孪生配置|
|params.sceneId|string|是|场景 ID|
|params.dimensions|string|是|维度 ID|
|params.nameAnd|array|否|合成词命中条件。仅 `isCompose="1"` 时生效|
|params.nameOr|string|否|OR 名称匹配条件|
|params.nameNot|array|否|合成词排除条件。仅 `isCompose="1"` 时生效|
|params.vector|string|否|向量配置，示例为空字符串|
|params.englishName|string|否|英文名称|
|params.japaneseName|string|否|日文名称|
|params.yueName|string|否|粤语名称|
|params.isRoot|string|是|是否根标签，`"0"` 否，`"1"` 是|
|params.segmentingAgain|string|是|是否二次分词，`"0"` 否，`"1"` 是|
|params.isCompose|string|是|是否合成词，`"0"` 否，`"1"` 是|
|params.pinyin|string|否|拼音|
|params.privateIds|array|否|私有 ID 列表|
|params.name|string|是|标签名称|
|params.weight|integer|是|权重|
|params.englishHom|string|否|英文谐音纠错词|
|params.japaneseHom|string|否|日文谐音纠错词|
|params.yueHom|string|否|粤语谐音纠错词|
|params.homophonic|string|否|中文谐音纠错词|
|params.viewTag|string|是|展示标签名，一般与 `params.name` 保持一致|
|params.privateId|string|否|私有 ID|
|params.privateName|string|否|私有名称|
|params.extendType|string|否|扩展类型|
|params.extendContent|string|否|扩展内容|

谐音字段说明：

- 谐音字段用于搜索纠错召回。例如标签为 `大衣` 时，用户可能输入 `大一`，配置中文谐音词后，搜索 `大一` 也可以匹配到 `大衣` 标签。
- `homophonic` 用于配置中文谐音纠错词。
- `englishHom`、`japaneseHom`、`yueHom` 分别用于配置英文、日文、粤语的谐音纠错词。

合成词字段说明：

- `isCompose="1"` 时，`nameAnd` 和 `nameNot` 生效；`isCompose="0"` 时，这两个字段不生效。
- `nameAnd` 用于填写合成词命中条件。每个元素使用 `/` 分隔多个标签，表示商品需要同时具备这些标签。
- `nameNot` 用于填写合成词排除条件。商品具备任一排除标签时，不打上该合成词标签。
- 请求参数使用驼峰字段 `nameNot`，返回体中对应字段为下划线格式 `name_not`。
- `nameOr` 用于填写 OR 名称匹配条件；无值时可传空字符串，抓包示例中也出现过 `"undefined"` 字符串。

示例：

```json
{
  "is_compose": 1,
  "name": "高尔夫t恤",
  "name_and": [
    "高尔夫/上装",
    "高尔夫/t恤"
  ],
  "name_not": [
    "马甲",
    "夹克"
  ]
}
```

`高尔夫t恤` 是合成词标签，表示商品同时具备 `高尔夫` 和 `t恤` 标签，或同时具备 `高尔夫` 和 `上装` 标签，且不具备 `马甲` 或 `夹克` 标签时，会被打上此标签。

### 2.3 拉黑/取消拉黑接口

#### 接口描述

更新指定标签的拉黑状态。标签拉黑用于替代删除功能；当不希望某个标签继续生效时，可将该标签拉黑。`isBlack=0` 表示正常，`isBlack=1` 表示拉黑。

#### 接口 URL

`POST {baseUrl}/admin/tag/updateTagInfo`

#### 鉴权要求

```http
authorization: Bearer <from-controlled-secret-provider>
content-type: application/json;charset=UTF-8
```

#### 请求参数

|参数名|类型|是否必填|说明|
|---|---|---|---|
|params|object|是|业务参数对象|
|params.id|string|是|标签节点 key|
|params.sceneId|string|是|场景 ID|
|params.tagId|string|是|标签业务 ID|
|params.isBlack|integer|是|拉黑状态，`0` 正常，`1` 拉黑|

#### 请求示例

```bash
curl 'https://kg.example.test/admin/tag/updateTagInfo' \
-H 'authorization: Bearer <from-controlled-secret-provider>' \
  -H 'content-type: application/json;charset=UTF-8' \
  --data-raw '{"params":{"id":"1519023070638899200","sceneId":"638749299500777472","tagId":"1120357226998923264","isBlack":1}}'
```

#### 返回参数

|参数名|类型|说明|
|---|---|---|
|code|integer|状态码|
|message|string|响应消息|
|data|object|更新结果|
|data.properties.is_black|integer|拉黑状态，`0` 正常，`1` 拉黑|
|data.properties.update_time|string|更新时间|
|data.properties.scene_id|string|场景 ID|
|data.properties.tag_id|string|标签业务 ID|
|data.properties._key|string|标签节点 key|

#### 返回示例

```json
{
  "code": 1,
  "message": "success",
  "data": {
    "id": null,
    "key": null,
    "revision": "_ltNH2wq---",
    "properties": {
```

## 3. 标签关系接口

### 3.1 relationships 取值与关系规则

`params.relationships` 用于指定标签关系类型。

|关系类型|ID|建关系条件|字段方向|召回或打标含义|
|---|---|---|---|---|
|从属|`902227092548485120`|只有根标签与根标签之间能建立从属关系|`params.tagId` 是子标签，`params.responseTagId` 是父标签，表示 `tagId` 从属于 `responseTagId`|通过父级标签能召回所有打上子级标签的商品。例如 `tagName=半身裙`、`responseTagName=裙子`，搜索 `裙子` 时会召回打上 `半身裙` 标签的商品|
|同义|`902227138815852544`|只有非根标签与根标签之间能建立同义关系|`params.tagId` 是非根标签，`params.responseTagId` 是根标签，表示 `tagId` 同义于 `responseTagId`|具备同义关系的标签召回商品相同。例如 `tagName=鞋子`、`responseTagName=鞋履`，搜索 `鞋子` 时也会召回打上 `鞋履` 标签的商品|
|互斥|`902227674009042944`|只有根标签与根标签之间能建立互斥关系|`params.tagId` 与 `params.responseTagId` 是互斥标签|具备其中某一标签的商品不会打上另一个标签。例如 `tagName=男性`、`responseTagName=女性`|

补充规则：

- 标签关系更新接口不能更新 `tagId`、`tagName`、`responseTagId`、`responseTagName`。
- 需要调整关系两端标签时，先删除原标签关系，再新建标签关系。
