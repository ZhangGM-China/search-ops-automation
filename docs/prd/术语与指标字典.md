## 1. 使用规则

本字典是 PRD 体系中业务术语和指标口径的唯一来源。功能 PRD 应引用本文件，不得自行改变同名指标的分子、分母、窗口、聚合方式或空值规则。

每个指标必须能回答以下问题：

- 统计对象是谁。
- 数据日期和比较日期是什么。
- 分子、分母和去重单位是什么。
- 多 Query 或多日如何聚合。
- 数据不足、分母为零或部分缺失时返回什么。
- 页面展示的是比例、百分比、百分点、数量、时长还是成本。

无法满足这些条件时，指标状态为“不可计算”，不得补 0、沿用前值或生成确定性结论。

## 2. 基础术语

| 术语 | 业务定义 |
| --- | --- |
| 品牌 | 一套独立数据、配置、权限和治理边界的业务主体。跨品牌数据不得混合计算或执行动作。 |
| Query | 用户提交给品牌搜索系统的搜索词。展示保留业务可识别原文；去重、实验分组或治理对象匹配使用已确认的业务身份规则。 |
| Query 展示值 | 面向运营人员展示并保留业务语境的原始 Query 文本。展示值不得被规范化值或治理载荷覆盖。 |
| Query 规范化身份 | 用于同一数据域内去重、匹配和统计的稳定身份。规范化规则必须有版本；同一任务、实验或追踪批次在建立时冻结所用版本。 |
| Query 治理身份 | 实际生产动作所作用的业务对象身份，可因品牌的人群词、过滤条件或治理载荷规则与展示值不同。 |
| 主任务仲裁键 | 用于决定 Top Query、无结果词等治理入口由谁承担主任务，固定由“品牌 + 治理身份 + 数据日 + 身份规则版本”组成。同一仲裁键同一时刻只能有一个主任务拥有治理写入协调权。 |
| 动作冲突键 | 用于阻止具体写动作重复或相互污染，固定由“主任务仲裁键 + 业务作用域 + 目标对象”组成。业务作用域描述 Query 排序、商品可见性、标签桶或知识关系等实际影响范围；存在明确目标对象时必须纳入。 |
| Top Query | 在指定品牌和数据日期内，按品牌配置的排序指标和范围进入日常巡检集合的 Query。Top Query 是每日巡检入口，不等同于“异常 Query”。 |
| 异常 Query | 已有业务证据表明至少一个检查项存在风险，或数据采集失败导致无法确认健康的 Query。 |
| 治理 | 从发现问题、节点检查、动作、验证到主链结束的完整业务过程。 |
| 检查项 | 对 Query 某一业务维度的独立判断，例如召回、相关性或排序。价格已退役，断码独立运行。 |
| 治理动作 | 会改变搜索结果、搜索配置、商品可见性或知识关系的业务操作。纯诊断、查询、评分和展示不属于治理动作。 |
| 治理任务 | 一个品牌、一个 Query、一个数据批次的一次治理闭环载体。重试或重新规划不应被误计为新的业务任务。 |
| 治理前快照 S0 | 本轮动作执行前保存的商品结果和排序，只用于前端治理前展示与对比。 |
| 实时结果 | 节点开始前或动作后通过 Mixed 重新获取的当前商品结果；结果变化后不得复用旧结果。 |
| 终态 | 当前任务处理周期无需系统自动继续推进的状态，包括 `completed`、`manual_required`、`failed`、`cancelled`、`skipped`、`superseded`。只有 `completed` 属于有效治理完成；其余状态表示人工、失败或生命周期收口。 |
| 配置值 | 由当前生效的业务配置提供的数值或开关。优先级为：品牌级有效配置 > 全局有效配置 > 无可用配置。不得把页面展示默认值或代码兜底值描述成已确认业务规则。 |
| 数据不足 | 输入缺失、窗口样本不足、分母无效或质量门禁不通过，导致不能形成该指标或判断。数据不足不是 0，也不是健康。 |

## 3. 日期与时间窗口

| 术语 | 业务定义 | 空值或异常规则 |
| --- | --- | --- |
| 运行日期 | 系统启动某次日常流程的自然日。 | 只用于任务运行归属，不替代数据日期。 |
| 数据日期 | 指标实际所属的业务自然日。昨日数据指运行日期前一个自然日，除非数据源明确提供其他已完成批次。 | 数据日期不明确时，不得把数据纳入日指标或效果比较。 |
| 监测日期 | 系统对固定对象进行观测、验证或追踪的自然日。 | 可与数据日期不同，展示时必须分别标识。 |
| 上一有效数据日 | 严格早于运行日期、数据源已完成且通过完整性校验的最近一个数据日期。 | 不能仅因某日存在部分记录就认定有效；候选日不完整时继续向前查找。找不到时任务标记数据不足，不回退到运行日或补 0。 |
| 动作日期 | 治理动作实际进入执行结果的自然日。 | 仅有计划时间时不得填充动作日期。 |
| 实验样本基准日 | 实验组和对照组锁定基线指标所对应的数据日期。 | 基线不完整时实验不得产生有效效果结论。 |
| 自然日窗口 | 按连续日历日期计算的窗口，包含没有业务数据的日期。 | 缺失日保留缺失，不补 0。 |
| 有效数据日窗口 | 从目标日期之前向前选取存在有效数据的不同数据日期；同一数据日重复记录只计一次。 | 实际有效日不足配置要求时，标记数据不足。 |
| 近期窗口 | 由品牌级或全局配置决定的有效历史窗口，用于趋势、骤降和近期均值。 | 配置缺失或样本不足时，不输出依赖近期窗口的比较结论。 |
| 治理后追踪窗口 | 从动作生效后开始，用于观察 CTR/CVR 或问题恢复情况的配置型窗口。 | 动作未执行、未确认生效或日数据不足时，不进入有效追踪样本。 |

时间口径规则：

- 所有“近 N 日”必须在具体功能 PRD 中明确是自然日窗口还是有效数据日窗口，并说明 N 来自哪一级配置。
- 历史窗口只使用目标数据日期之前的数据，不得把当前日或未来日混入基线。
- 同一数据日期存在多条记录时，业务上只保留该日最终有效版本参与窗口计算；如何确定最终版本由技术设计说明。
- 时长均以业务事件的实际开始到实际结束计算。缺少任一时间点时记为不可计算，不写成 0。

## 3.1 Query 身份冻结与冲突规则

- 任务建立时同时保存展示值、规范化身份、治理身份和身份规则版本；任务存续期间不随规则升级静默改变。
- 规则升级只影响新任务或经明确批准的重建，不自动改写历史任务、实验样本、动作或追踪记录。
- 同一主任务仲裁键存在进行中主任务或实验对照组保护时，其他入口不得争抢治理写入协调权；同一动作冲突键存在待人工、执行中、结果未知或已执行动作时，其他入口不得创建冲突写动作。
- 两个展示值映射到同一治理身份时，可以分别展示和统计，但主任务必须按仲裁键唯一确定，生产动作必须按动作冲突键去重并明确影响范围。
- 一个展示值因品牌过滤条件映射到不同治理身份时，不得仅按文本相同合并动作。
- 身份无法唯一确定或版本冲突时状态为数据不足或身份冲突，不得自动执行。
- 业务作用域必须描述动作实际影响范围，例如当前 Query 排序、商品可见性、标签桶或知识关系；不得用入口名称代替作用域。
- 数据日用于隔离不同业务批次；跨数据日仍存在未收口外部动作时，必须通过动作目标检查阻止冲突写入，不能仅因冲突键的数据日不同而绕过。

## 4. 流量与转化指标

### 4.1 UV 与 PV

| 指标 | 定义 | 聚合规则 | 空值规则 |
| --- | --- | --- | --- |
| Search UV | 在指定品牌、Query 和数据日期内发起搜索的去重用户数。 | 多 Query 汇总时，若数据源不能跨 Query 去重，必须标记为“Query Search UV 之和”，不得表述为品牌去重搜索人数。 | 缺失为不可计算；真实 0 可保留 0。 |
| Search PV | 在指定品牌、Query 和数据日期内发生的搜索次数。 | 多 Query 可求和，但不得与 UV 混用。 | 缺失为不可计算；真实 0 可保留 0。 |
| Click UV | 在指定品牌、Query 和数据日期内发生搜索结果点击的去重用户数。 | 组级 CTR 优先使用分子求和后统一相除。 | 缺失时 CTR 不可计算，除非存在经确认可兼容的冻结率值。 |
| Add-to-cart UV | 在指定品牌、Query 和数据日期内发生加购的去重用户数。 | 组级 ATC 优先使用分子求和后统一相除。 | 缺失时 ATC 不可计算。 |
| Purchase UV | 在指定品牌、Query 和数据日期内发生购买的去重用户数。 | 组级 CVR 优先使用分子求和后统一相除。 | 缺失时 CVR 不可计算，除非存在经确认可兼容的冻结率值。 |

### 4.2 CTR、ATC 与 CVR

| 指标 | 公式 | 展示单位 | 规则 |
| --- | --- | --- | --- |
| Query CTR | `Click UV / Search UV` | 百分比 | 分母为 0 或缺失时不可计算。 |
| Query ATC | `Add-to-cart UV / Search UV` | 百分比 | 分母为 0 或缺失时不可计算。 |
| Query CVR | `Purchase UV / Search UV` | 百分比 | 分母为 0 或缺失时不可计算。 |
| 品牌 CTR / ATC / CVR | 使用品牌用户行为口径对应的分子与品牌 Search UV 计算 | 百分比 | 不得用 Query 率值简单平均替代品牌整体指标。 |
| Query 集合 CTR / ATC / CVR | `集合内有效分子之和 / 集合内对应 Search UV 之和` | 百分比 | 只纳入分子、分母均有效且通过数据质量要求的样本。 |

展示规则：

- 比例展示为百分比；两个比例相减展示为百分点（pp）。
- “提升 X%”仅用于相对变化；“提升 X 个百分点”用于绝对差值，两者不得混用。
- 如果只能取得率值和对应 Search UV，可用 `率值 × Search UV` 做兼容加权；必须标记为兼容数据，不能声称拥有真实分子。

### 4.3 Top Query UV 覆盖率

| 项目 | 定义 |
| --- | --- |
| 中文名称 | Top Query UV 覆盖率 |
| 业务公式 | `Top Query 的 Query Search UV 之和 / 品牌 Search UV` |
| 分子 | 同一品牌、同一数据日期、进入当前 Top Query 集合的 Query Search UV 之和 |
| 分母 | 同一品牌、同一数据日期的品牌 Search UV |
| 展示单位 | 百分比 |
| 空值规则 | 分母缺失或为 0 时不可计算；Top Query 明细不完整时不得以已返回部分冒充完整覆盖率 |
| 历史兼容语义 | 对外接口可能保留历史命名，但当前业务语义始终是 UV 覆盖率，不得根据历史名称恢复为 PV 口径；具体字段映射见 [API 总纲](../API.md) |

该指标反映当前 Top Query 集合覆盖的 Query 搜索流量规模，不代表跨 Query 去重后的用户覆盖人数。

## 5. 召回与商品指标

| 指标 | 定义 | 配置与空值规则 |
| --- | --- | --- |
| 返回商品数量 | 指定 Query 在一次有效搜索快照中的可用结果总数。 | 搜索失败与真实返回 0 必须区分；失败时为不可用，不能判为无结果。 |
| 无结果 | 有效搜索成功且返回商品数量为 0。 | 不依赖可配置阈值。 |
| 少结果 | 有效搜索成功且返回商品数量高于 0，但低于当前生效的少结果阈值。 | 阈值来自品牌级配置，缺失时不得自动判定少结果或健康。 |
| 结果数量骤降 | 当前有效返回商品数量相对近期有效数据日基线的下降达到当前生效阈值。 | 历史窗口、最低有效样本数和下降阈值均来自配置；任何一项缺失时标记数据不足。 |
| 断码率 | `不可售尺码数量 / 纳入判断的全部尺码数量`。 | 尺码范围、核心尺码和风险阈值由品牌配置定义；分母为 0 或尺码明细无效时不可计算。 |
| 价格偏离度 | 当前商品价格相对同一有效 Query 结果集参考价格的偏离程度。 | 参考价选取、纳入商品、异常值处理和阈值来自品牌配置；数据不足时只展示事实，不生成自动动作。 |
| 不相关 Query 数 | 指定品牌和数据日期内，相关性检测结果包含至少一个不相关商品的 Query 数。 | 按 Query 去重计数；不相关商品数仍单独统计，不以商品数量替代 Query 数。 |

## 6. 健康与治理效率指标

所有比率必须在同一品牌、同一数据日期或明确的统计窗口内计算，并在页面展示分子、分母或可下钻明细。

| 指标 | 公式 | 分母范围与空值规则 |
| --- | --- | --- |
| Top Query 巡检覆盖率 | `已建立有效巡检任务的治理身份数 / 本期目标 Query 治理身份数` | 同一品牌、同一数据日期按主任务仲裁键去重；资格规则在目标集合形成前排除的 Query 不进入分母。任务创建失败、取消或尚未创建仍保留在分母；分母为 0 时不可计算。跨品牌或跨日期不得合并后直接计算。 |
| Query 健康率 | `最终结论为健康的 Query 数 / 已完成有效评估的 Query 数` | 数据采集失败、仍在运行、等待人工且未完成评估的 Query 不进入分母；同时单独展示这些数量。分母为 0 时不可计算。 |
| 治理处理率 | `已进入有效诊断并形成最终处理结果的 Query 数 / 本期应处理 Query 数` | 最终处理结果可为完成、需人工或失败，但仅“已创建任务”不算已处理。分母为 0 时不可计算。 |
| 自动治理率 | `无需人工确认且完成验证的 Query 数 / 已形成治理处理结果的 Query 数` | 纯健康无需动作的 Query 不计为自动治理；分母为 0 时不可计算。 |
| 人工介入率 | `最终需要人工决策或人工执行的 Query 数 / 已形成治理处理结果的 Query 数` | 同一 Query 在窗口内只计一次，以最终是否需要人工为准。分母为 0 时不可计算。 |
| 动作执行成功率 | `执行成功的动作数 / 已发起执行的动作数` | 仅提议、等待审批或被禁止的动作不进入分母；执行后验证失败仍属于“执行成功但治理验证未通过”。 |
| 动作验证通过率 | `验证通过的动作数 / 已完成验证的动作数` | 尚未验证、验证数据不足单独展示，不进入分母。 |
| 回滚率 | `已执行回滚的动作数 / 已成功执行的可回滚动作数` | 不可回滚动作不进入分母；回滚建议但未执行不计入分子。 |
| 治理完成率 | `任务状态为 completed 的任务数 / 本期应完成任务数` | 需人工、失败、取消、运行中分别展示，不得并入完成；跳过与替代按下方特殊终态口径处理。 |
| 通过率 | `流程完成且相关性检测通过的 Query 数 / 检查 Query 总数` | 分子要求任务流程已完成且相关性节点结果不含不相关商品或拉黑候选；召回、断码、重排序、商品数量等异常不扣分。缺少相关性检测记录或相关性节点失败计为未通过；当天未启用相关性检测时不可计算，展示为空值。分母为当天纳入检查的 Query 总数。 |
| 相关性检测准确率 | `当前仍处于拉黑状态的不相关商品组合数 / 大模型判定不相关的商品组合数` | 计数单位为 (Query, 商品) 组合：同一商品在不同 Query 下判定不相关、被拉黑或取消拉黑，分别计数；同一批次内相同组合重复判定只计一次。分子按本地拉黑动作记录投影当前状态（最新一条拉黑/取消拉黑为准），读取时实时计算：自动拉黑模式下批次完成后为 100%，运营取消误判拉黑后下降；人工审批模式下初始为 0，运营确认拉黑后上升。趋势历史点同样按当前状态投影，会随后续人工操作变化。批次判定不相关组合数为 0、或批次缺少组合清单（旧格式未回填）时不可计算，展示为空值；周期聚合按 Σ分子 / Σ分母，不做日均。 |

### 6.1 任务集合、特殊终态与分母口径

任务统计先确定目标集合，再按主任务仲裁键和替代链去重。统一口径如下：

| 情况 | 应处理分母 | 治理处理率分子 | 应完成分母 | 治理完成率分子 | 耗时与成本 |
| --- | --- | --- | --- | --- | --- |
| 目标集合形成前被资格规则排除 | 不纳入 | 不纳入 | 不纳入 | 不纳入 | 不产生治理任务耗时与成本 |
| 建立任务后按有效业务规则进入 `skipped` | 纳入 | 纳入，表示已形成有效跳过结论 | 不纳入 | 不纳入 | 未进入 `running` 时不产生治理耗时；进入过 `running` 的任务不得再标记 `skipped` |
| `cancelled` | 纳入 | 不纳入 | 纳入 | 不纳入 | 进入过 `running` 时记录实际三类耗时；从未进入 `running` 时治理耗时为空，不写 0 |
| `superseded` 原任务 | 排除，由接管任务代表该对象计一次 | 排除 | 排除，由接管任务计一次 | 排除 | 原任务保留历史耗时和成本审计；当前批次聚合由接管任务承接替代链的非重复耗时与成本，只计一次 |
| `manual_required` | 纳入 | 纳入，表示已形成需人工处理结果 | 纳入 | 不纳入 | 分别记录活跃处理、人工等待和端到端耗时 |
| `failed` | 纳入 | 纳入，表示已形成失败结果 | 纳入 | 不纳入 | 记录实际活跃处理和端到端耗时，人工等待仅在确实进入过人工等待周期时累计 |
| `completed` | 纳入 | 纳入 | 纳入 | 纳入 | 记录实际三类耗时 |

补充规则：

- “治理处理率”衡量是否形成有效处理结果，因此 `manual_required`、`failed` 和建立后有效 `skipped` 进入分子；它不等于成功率。
- “治理完成率”只把 `completed` 计入分子。
- `running`、`pending` 不进入任何终态结果分子，但仍留在对应分母并单独展示进行中数量。
- `superseded` 替代链无论包含多少历史任务，在当前批次的数量、耗时和成本聚合中都由最终接管任务代表一次。
- 从未进入 `running` 的任务不产生活跃处理、人工等待或端到端治理耗时；创建到跳过、取消或替代的管理延迟如需监控，应作为独立生命周期延迟，不混入治理耗时。

“品牌平均治理分”若保留展示，必须同时标明聚合方式。默认不得把它与 Query 健康率混为一谈：治理分是评分结果，健康率是状态计数比率。若采用流量加权，权重应为同日有效 Query Search UV；缺失权重的 Query 不得静默按 0 加权。

## 7. 成本与时效指标

| 指标 | 定义 | 聚合与空值规则 |
| --- | --- | --- |
| 活跃处理耗时 | 系统实际进行采集、检查、执行和验证的累计时间，不含人工等待及任务暂停。 | 缺少环节起止时间时不可计算；各活跃区间不得重叠重复累计。 |
| 人工等待耗时 | 从任务进入 `manual_required` 到有效人工结果回填或任务取消的累计时间。 | 尚在等待时持续计时；多次人工等待分别累计。 |
| 端到端耗时 | 从任务首次进入 `running` 到进入当前终态的墙钟时间，包含活跃处理、人工等待和其他暂停。 | 进行中任务展示已历时；必须与活跃处理耗时分开展示。 |
| 检查项耗时 | 对应检查项从开始到产生结果的实际耗时。 | 超时应记录为超时结果及实际等待时长。 |
| 动作验证耗时 | 从开始获取动作后状态到形成验证结论的实际耗时。 | 即使不调用模型也必须记录真实耗时，不得固定为 0。 |
| Token 用量 | 实际模型调用返回的输入与输出 Token 之和，并按产生该调用的业务环节归属。 | 确定性规则为 0；模型调用但无法取得 usage 时标记“未知”，不得伪装为 0。 |
| 单 Query Token | 同一治理任务内所有真实模型调用 Token 之和。 | 按实际调用节点归属；确定性节点为 0。 |
| 单品牌日 Token | 同品牌、同数据日期有效治理任务的 Token 之和。 | 缺失 usage 的任务数量需同时披露。 |
| 单 Query 成本 | 当前任务的可计费模型、外部服务或人工成本汇总。 | 未配置单价或计费口径时不可计算，不以 Token 数冒充货币成本。 |

Token 和耗时是可观测指标，不是治理质量指标。低 Token 或短耗时不能替代问题是否解决的业务验证。

## 8. 效果观察指标

### 8.1 基线与当前值

- 基线值来自实验样本锁定时的有效基准日数据，不随后续数据回填变化。
- 当前值来自指定观测日或明确的累计窗口。
- 实验组和对照组必须使用相同数据日期、相同有效性条件和相同聚合公式。
- 未观测、污染或数据质量失败的样本不得补 0。

### 8.2 加权口径

对任一组 `g`：

- 组 CTR = `有效 Click UV 之和 / 有效 Search UV 之和`。
- 组 CVR = `有效 Purchase UV 之和 / 有效 Search UV 之和`。
- 当缺少真实分子但存在冻结率值和 Search UV 时，可采用 `率值 × Search UV` 的兼容加权，并标注数据来源。
- 不允许对 Query CTR/CVR 做简单算术平均。

### 8.3 变化与对照差值信号

| 指标 | 公式 | 展示 |
| --- | --- | --- |
| 组内绝对变化 | `当前组指标 - 基线组指标` | 百分点 |
| 组内相对变化 | `(当前组指标 - 基线组指标) / 基线组指标` | 百分比；基线为 0 时不可计算 |
| 对照差值信号 | `实验组组内变化 - 对照组组内变化` | 与组内变化保持相同单位 |

本产品当前输出“治理效果对照观察”或“效果信号”，不输出严格因果归因。结论只能是：

- 存在正向信号。
- 未观察到明确差异。
- 实验组弱于对照组。
- 数据不足，无法判断。
- 样本污染，结论不可靠。

“显著提升”只有在另行批准统计显著性规则后才能使用；当前不得作为产品结论。

### 8.4 未观测与污染

- 未观测：该样本在指定数据日没有有效指标。该日不进入分子、分母，也不退出固定样本集合。
- 污染：样本在观察期间受到不符合分组规则的治理或人工干预。污染日及之后是否剔除，以实验 PRD 的已批准规则为准。
- 当日质量门禁未通过时，不生成当日净变化信号，但仍展示缺失、污染、任务和动作事实。

## 9. 配置缺失的统一安全行为

| 缺失内容 | 业务行为 |
| --- | --- |
| 判断阈值 | 保留原始事实，状态标记为数据或配置不足；不得判健康或自动执行。 |
| 历史窗口或最低样本要求 | 不生成趋势、骤降或相对基线结论。 |
| 动作执行模式 | 动作不得自动执行，进入人工确认或禁止执行。 |
| 自动执行额度 | 视为无可用自动额度，不发起生产写操作。 |
| 统计分母 | 指标不可计算，不补 0。 |
| 模型 Token usage | 标记未知，并披露存在模型调用。 |
| 实验基线、样本完整性或污染证据 | 效果结论不可用，展示质量异常原因。 |

## 10. 验收场景

### 场景一：覆盖率兼容语义

- Given 对外接口使用历史兼容命名，且数据提供 Top Query Search UV 之和与品牌 Search UV。
- When 页面和报表展示该指标。
- Then 名称必须为“Top Query UV 覆盖率”，按 UV 口径计算，不得展示为 PV 覆盖率。

### 场景二：分母为零

- Given 某 Query 的 Search UV 为 0。
- When 计算 CTR 或 CVR。
- Then 指标应为不可计算，不得返回 0% 或无穷值，也不得据此判定健康或异常。

### 场景三：历史样本不足

- Given 当前 Query 的有效历史数据日少于配置要求。
- When 系统尝试判断结果数量骤降或近期转化变化。
- Then 输出“数据不足”，保留当前事实，不生成骤降或趋势结论。

### 场景四：实验组加权

- Given 组内各 Query 的 Search UV 不同。
- When 计算组 CTR/CVR。
- Then 使用分子求和除以 Search UV 求和，不得简单平均各 Query 率值。

### 场景五：模型调用缺 usage

- Given 某环节实际调用了模型，但未返回 Token usage。
- When 页面汇总 Token。
- Then 该环节标记为“Token 未知”，不得显示为“确定性逻辑”或 Token 0。
