# 管理后台页面需求

## 0. 页面配置中心

配置页在“模型配置”后提供“页面配置”Tab，以“品牌总览”和“品牌详情”作为两大配置区。注册表使用稳定 key 和类型化定义驱动界面，支持 metric list 的合法候选、最小/最大项数与排序。

### 0.1 品牌总览

- **数据看板**位于品牌总览日期切换器和品牌卡片之间，由独立开关控制整体展示；开启时提供 3～6 个可配置指标，按实际项数平分一行。数值统计按选定日期汇总全部品牌；比率用所有品牌的合计分子和分母重新计算，不对品牌比率做简单平均。
- **品牌卡片**右上角主指标可从品牌卡片指标中选择一项，默认 Query 数量；下方辅助指标支持 2～4 项，可增删和排序，并按实际项数平分一行。窄屏宽度不足时，指标单元格仍保持一行并省略过长标签。独立开关控制耗时与 Token 展示，以及“运营数据”按钮。
- **运营数据**抽屉的基础数据默认可为空，最多 20 项。转化率设置在同一行配置“图表”“表单”两个显示开关，并共用转化率指标列表；品牌卡片中的“运营数据”关闭时不展示该配置容器。

品牌总览可配置指标包括 Query 数量、无召回率、通过率、AI 处理、待处理、不相关 Query 数、重排序 Query 数、断码商品数、商品准确率、Token 消耗和耗时。无召回率为 L0～L2 均无商品的 Query 数除以检查 Query 总数；通过率为流程完成且相关性检测通过的 Query 数除以检查 Query 总数（仅相关性检测未通过计为未通过，召回、断码、重排序、商品数量等异常不扣分；缺少相关性检测记录或相关性节点失败计为未通过；当天未启用相关性检测时展示为空值）；AI 处理为 AI 完成且无需人工介入的 Query 数，人工执行或仍待人工确认的治理动作不计入；待处理按 Query 去重，包含当前 `manual_required` 状态的 Query，以及存在待人工确认、需人工复核、执行结果待确认或回滚失败动作的 Query，不含 Agent 方案生成中或自动动作待执行的 Query，人工处理后动态减少。比例无检查数据时显示为空值而非 0%。

### 0.2 品牌详情

- Query 列表的 Query 卡片将转化指标开关与卡片指标调整合并为同一行；开启时配置 2～6 项可用指标（PV、UV、CTR、CVR、处理耗时、Token 消耗），关闭时隐藏调整入口但保留指标配置。
- Query 详情中的“执行概览”“昨日数据”及“治理方案”“效果对比”“相关性规则”统一放在同一配置容器；昨日数据开启时可配置 2～6 项实际有数据来源的 PV、UV、CTR、CVR、ATC、点击 UV、加购 UV 或购买 UV。

### 0.3 交互、权限与兼容

- 所有登录用户读取有效配置；仅平台管理员可修改。
- 页面配置缺失、读取失败或新增 key 未被客户端识别时，沿用旧页面可见状态的默认值，避免内容意外隐藏。
- 支持“修改配置—取消—保存”，metric list 弹窗完整回显候选指标，可用开关选择展示项并通过拖动调整顺序，同时服从每项 min/max 约束。用 `expectedVersion` 做乐观并发控制；版本冲突不得覆盖其他管理员修改。
- 保存经过既有 ActionGateway、审计、持久化和回读链路；配置只控制展示和必要的只读请求，不改变治理动作或业务事实。
- schema v1 的运营数据开关、昨日数据开关和品牌卡片三个辅助指标迁移到 v2 稳定 key。未来回读和保存使用 v2，不再返回旧配置 key。

## 1. Query 治理页面

- Query 列表检查项状态、顶部筛选项和 Query 详情执行概览按品牌及治理日期统一计算可见范围。系统配置关闭后，后续治理日期无检测事实时隐藏对应模块；关闭前历史记录，以及关闭后仍存在的实际执行或断码恢复事实继续展示。现有状态文案保持不变。
- 展示治理前 `S0` 和当前实时 Mixed 两类商品结果。
- 展示召回、排序、相关性节点的待执行、执行中、已执行、已跳过、异常状态及说明。
- “治理方案”Tab 展示 KG Agent 逐步调整、AI 重排序、拉黑商品、降桶商品、恢复降桶商品五类策略。每项显示原因、状态和单项执行按钮，Tab 栏右侧提供一键执行。
- 断码作为独立周期记录展示多次，不作为主链节点。
- 展示 KG Agent 方案状态、世界事实警告、相关性规则和模型配置。
- KG 方案按执行顺序展示创建标签、创建关系、删除标签等步骤，并说明是召回数量不足、数量下降还是错误召回触发；错误召回需展示对应商品。AI 重排序展示策略文案和待调整商品数，点击打开商品列表，再点击商品打开详情。
- 拉黑商品显示拉黑理由；降桶商品显示执行时断码率；恢复降桶商品用向右箭头展示“执行降桶时断码率 → 恢复时断码率”。每项状态至少包含待执行、执行中、已执行、执行失败。自动拉黑和降桶在可取消时显示取消按钮。
- 在“相关性检测配置”中维护检测分桶：默认选中 Mixed 的 L1/L2 叶子分桶（编码完全召回、商品名召回、编码纠错召回、商品标签召回、白名单/主分类机器召回、二次分词召回），用户可追加其他已定义分桶；页面使用中文名称回显，运行时保存稳定 bucket ID。选择全部已知分桶时表示不按 bucket 过滤，缺失或未知 bucket 的商品也进入检测，用于兼容没有分桶体系的品牌。Atlas 默认额外启用 `Dynamic`（动态召回），其他品牌仍使用六个 L1/L2 默认分桶。
- 展示已记录的 Token 总量，以及每个 Query 的相关性 Token 消耗。用量缺失的 Query 单独明确标记；部分缺失时仍显示已知消耗，无模型调用与用量未知必须区分。共享调用在总量中不得重复计入。
- 不展示 Planner、Evaluator、健康评分、旧 Agent Loop 或 Ops Team 状态。

## 2. 交互与权限

页面通过 API 读取数据和提交受控动作；前端不直连外部搜索或知识图谱服务。取消拉黑理由仅可查看（审计记录），相关性规则支持查看、编辑及 AI 整理，不提供停用入口；审计记录以「规则变更记录」展示操作人与北京时间，不展示商品 SKU。

## 3. 验收场景

- Given Query 存在治理动作，When 用户打开详情，Then 页面展示 S0、实时结果和治理方案，不展示旧“治理记录”时间线。
- Given 某个 Query 的部分模型调用未返回用量，When 用户查看 Query 列表，Then 该 Query 显示已知 Token 与缺失标签，其他 Query 不误标，品牌总量仍正常显示已知合计。
