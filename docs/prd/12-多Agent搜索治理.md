# KG Agent 治理

## 1. 职责与业务定义

召回 KG Agent 处理无结果、少结果以及排除正常消失后的结果骤降；相关性根因 Agent 对同一 Query 的错误商品分组并生成 KG 修复策略。两者共享领域规则、只读工具、动作契约和执行器，保持独立 Prompt 和异步任务。主链不等待、不回流。

商品原始描述命中标签后，商品归到对应根标签。系统加工的商品标签用于解释召回路径，不能作为证明商品真实属性的独立证据。同义关系仅允许非根 → 根，同一非根只有一个根；从属仅允许根 → 根，方向为子 → 父，允许多父但禁止环。搜父类包含子类，搜子类不应扩展至父类的全部商品。

二次分词可能扩大召回；合成词按每组条件交集、组间并集及 nameNot 排除项解释；谐音词不能与已有标签冲突。isEnglish 表示英文分词开关，通常为 0。Mixed 包含人工、精准、相关、模糊、无库存及动态分桶，不能把总数增长视为正确标签召回增长。

## 2. 输入和调查

- 错误商品：工程侧先补齐商品详情、当前标签及检测原因，再统一传给根因 Agent。个例不改图谱；关系错误调整关系；二次分词、合成词或谐音属性错误更新标签。缺失证据单独标记 uncertain，不把系统标签当商品原始事实。
- 无结果/少结果：提供 Query、搜索筛选范围和实际数量。模型查询标签、双向关系及商品搜索，确认符合检索意图的供给和可修复原因，禁止仅为增加数量扩大语义。
- 结果骤降：工程侧比较紧邻前一天与当天相同检索范围的商品身份，批量检查消失商品上下架和当前 Query 黑名单。全部可由明确下架/拉黑解释则不触发骤降 KG 治理；仍有未解释消失时提供数量和最多 10 件代表商品、当前详情及可用历史证据。查询失败、身份不完整、仅 Top N 快照或历史缺失不能等同“正常消失”，记录证据不足并待复核。库存为零不能直接等同下架。无历史图谱证据不得断言关系昨天存在今天消失。
- 下架/拉黑排除只消除骤降问题，不自动取消独立的无结果/少结果检查。

## 3. 工具与策略

只读工具：精确标签查询、关系起点/终点/both 查询、Mixed 搜索、维度查询。sceneId 由品牌可信配置注入。关系起点使用 tagNameAcc，终点使用已文档化 resTagName 查询并精确过滤 responseTagName；自动分页，未读全时不允许据此断言不存在。

允许生成的策略只有新增标签、更新标签、拉黑标签、新增关系、更新关系、删除关系；不支持删除标签。拉黑标签通过 updateTagInfo 设置 isBlack=1，区别于 Query 下商品拉黑，并说明对整个场景召回的影响。

新增标签允许提出有证据支持的新名称，但不得虚构既有标签/关系 ID。新标签的后续关系通过前序步骤引用，由代码在创建回读后解析真实 ID。维度、场景和既有对象身份必须来自可信配置或工具结果。修改保留未涉及的既有属性。

## 4. 结构化方案与执行

保留现有 actions、causeGroups 和商品唯一分组。adjust 必须有动作；no_change 和 manual_review 不得带动作；每组包含结论、原因、证据、有序步骤及可用回滚记录。商品拉黑继续采用已批准的检测后独立流程，不等待 KG 根因分析。

模型不调用写接口。方案按 Agent 与涉及标签/关系工具的最严格执行模式执行。自动和人工执行均检查同一份图谱前提、参数来源、关系方向和环；随后走统一网关、幂等、审计和内容回读。搜索失败不得视为空结果；工具查询失败或证据不完整不得产出可执行方案。冲突检查仅比较相关图谱业务字段，搜索数量或返回顺序波动不属于图谱变更。

## 5. 验收

覆盖双向精确查询与分页、维度/场景解析、同义单根与从属无环、合成词与谐音、拉黑标签及内容回读、方案证据持久化、自动/人工相同门禁、骤降正常排除/部分异常/证据缺失，以及查询失败和虚构 ID 拒绝。
