# 每日治理主流程

| 字段 | 日期 |
| --- | --- |
| 创建时间 | 2026-07-23 |
| 最后更新时间 | 2026-10-08 |

## 1. 目标与范围

每日对启用品牌的治理 Query 执行固定顺序的检查、动作、验证和收口。断码由独立周期任务处理，不属于本主链；价格治理已退役。

## 2. 固定流程

```text
提取并筛选 Query
→ Mixed 获取并保存治理前快照 S0
→ 排序治理
→ 相关性检测
→ 召回结果检查（召回率检测、白名单/标签补全与召回数量检查；召回率检测按品牌开关启用，补召回动作支持自动执行/人工审批两种执行模式）
→ 主链结束
```

- 每个品牌每个监测周期建立一个批次，Query 和节点状态及时落库。
- 每个节点只使用待执行、执行中、已执行、已跳过、异常五种状态。
- 排序阶段全部 Query 收口后才进入相关性阶段；单个 Query 异常不阻塞其他 Query 或后续阶段。
- 召回异常和相关性拉黑比例达到配置阈值时，投递 KG Agent 异步任务；主链不等待、不回流。
- 节点动作经过权限、幂等、写后回读和验证；验证失败记录异常并继续后续 Query。
- 主链结束后不进入 Planner、Evaluator 或新的 Agent Loop。

## 3. 数据与页面

- 普通动态治理没有入选 Query 时，保留当日筛选结果并正常跳过，不执行治理动作。页面区别展示“无符合条件的 Query”、尚未运行和真实失败；检测数量为 0，准确率和 Query 平均指标无分母时显示“—”。A/B 实验使用独立固定样本取词逻辑，不受普通治理空选中集规则影响。

- `S0` 保存治理前商品和排序，始终用于前端治理前结果展示。
- 当前商品结果由实时 Mixed 获取；排序或拉黑导致结果变化后，后续节点重新调用 Mixed。
- 页面展示当前实时结果、治理前 S0、节点状态、动作记录和异常说明。

## 4. 异常与恢复

- 单个 Query 或节点异常只标记对应记录，不阻塞其他 Query。
- 所有节点状态和 Checkpoint 完成即落库；中断后跳过已完成部分，从第一个未完成节点继续。
- 节点执行中断时先按请求 ID、幂等键和权威回读确认外部状态，确认未执行后才重试。
- 外部事实全部不可用时当前节点记异常并继续后续节点；部分事实不可用时记录警告并使用可用事实。
- 日任务按品牌分段推进，完整选样及阶段顺序保持冻结。单次推进结束但节点尚未收口时仍为治理中；调度器在同一运行内按品牌轮转立即继续下一片段，让后面的品牌有执行机会。进程终止、租约失效或品牌关闭时停止开启新片段，交由既有恢复路径接管。
- 品牌关闭、治理关闭或已有同品牌任务占用时明确记录跳过原因；仅心跳变化或调度函数返回成功不算恢复。目标批次节点完成数增加或进入终态后才计入恢复数量。
- 主动分段退出不反复重试本轮已失败节点，避免错误 Query 阻塞剩余 Query。意外中断仍沿用既有错误恢复及外部动作回读规则。
- 尚未创建的历史品牌日期必须单独核对源数据和补跑清单，经确认后通过受控入口创建；已有工作流恢复不会自动补出缺失日期。

## 6. 验收场景

- Given 一个有效品牌批次，When 主链运行，Then 节点按固定顺序完成并在主链结束后不进入旧循环。
- Given 单个 Query 节点异常，When 批次继续，Then 其他 Query 和后续节点仍可执行且异常可见。
- Given 批次超过单次推进预算，When 后续恢复继续，Then 原 Query 集合不变、已完成动作不重复、所有节点最终收口。
- Given 品牌关闭，When 恢复扫描命中历史批次，Then 明确跳过且恢复数量不增加。
