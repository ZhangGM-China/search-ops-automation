# 无结果词治理

| 字段 | 日期 |
| --- | --- |
| 创建时间 | 2026-07-23 |
| 最后更新时间 | 2026-08-14 |

## 1. 模块目标

每日发现有购物意图但没有搜索结果的 Query，识别知识图谱缺失或错误，形成可审计、可执行、可验证、可回滚的修复闭环。

完整闭环包括：抽取、过滤、意图判断、根因诊断、动作计划、执行或人工确认、重新打标签、二次复查，以及失败后的人工调整或回滚。

## 2. 支持范围与触发条件

### 2.1 当前品牌范围

当前已具备数据来源的品牌：

- Summit
- HARBOR
- Riviera

ATLAS、Meadow 在数据来源补齐前不进入自动治理。品牌接入状态以 `docs/API.md` 的数据源契约为准。

### 2.2 日常触发

- 每日按品牌读取上一有效数据日的无结果 Query。
- 品牌必须启用无结果词治理。
- Query 指标需达到品牌配置的处理条件。
- 当前没有同品牌、数据日和 Query 的未终结等价任务。

### 2.3 人工触发

运营人员可对待处理 Query、暂停任务、失败任务或指定批次发起继续、重试、人工调整或回滚。人工操作仍受品牌权限、动作权限和生产授权约束。

### 2.4 与 Top Query 召回治理的跨链路仲裁

无结果词任务建立或恢复前，必须按术语字典定义的“主任务仲裁键”检查是否与 Top Query 召回治理冲突：

- 主任务仲裁键由“品牌 + 治理身份 + 数据日 + 身份规则版本”组成，同一时刻只能有一个主治理任务拥有治理写入协调权。
- Query 属于运行中效果观察的对照组时，本链路不得建立或执行治理动作，只保留受保护跳过证据。
- 已有一条链路进入执行或产生有效动作证据时，该链路保持主任务；另一链路只能引用、观察或等待。
- 两条链路都未执行时，按系统配置的业务优先级选择主任务；优先级缺失或冲突时转人工，不得自动写入。
- 两条链路共享同一治理对象的动作锁、已执行证据和外部状态；标签、关系等具体动作按“主任务仲裁键 + 业务作用域 + 目标对象”形成动作冲突键，等价动作只能执行一次。
- 验证由实际执行动作的主任务负责，另一链路引用结果；回滚只能由原动作归属任务发起或获得其明确移交。
- 主任务失败、取消或释放写入权后，本任务需重新检查最新事实、对照保护和已执行证据，再决定是否接管。

跨链路仲裁不合并两条业务任务的展示和诊断结论，只统一生产写入权、验证证据与回滚归属。

## 3. 输入与输出

### 3.1 输入

- 品牌、Query、统计日期及无结果次数、搜索流量等可用指标。
- 品牌排除词、处理阈值、执行模式、风险上限和停止条件。
- Query 历史“不处理”记录、治理记录和人工决策。
- 候选词语、知识图谱标签、维度、关系和现有配置。
- 写操作授权、当前环境、冷却状态和回滚可用性。

### 3.2 输出

- 购物意图判断与过滤原因。
- 无结果根因、证据、置信度和修复建议。
- 知识图谱候选动作、风险、执行模式和人工确认状态。
- 动作执行、暂停、继续、失败与回滚结果。
- 重新打标签与二次复查结果。
- Query、批次和品牌级统计及人工关注清单。

字段、接口和持久化契约见 `docs/API.md` 与现有 TSD。

## 4. 决策职责分层

### 4.1 确定性规则

由系统执行，不调用模型判断：

- 日期、品牌范围、排除词、任务去重和状态路由。
- 同一查询意图的结果复用。
- 动作顺序、暂停点、重试计数、冷却时间和停止条件。
- 权限、环境、风险门禁、幂等、审计与回滚检查。
- 二次复查是否达到配置的结果数量和相关性标准。

### 4.2 配置规则

由品牌或系统配置决定：

- 执行周期、流量阈值和单日处理量。
- 排除词与“不处理”记录有效期。
- 最大查询轮次、失败重试、冷却与复查等待时间。
- 检查商品范围、风险上限和动作执行模式。

具体数值不在 PRD 写死。配置缺失时不得由模型自行补造。

### 4.3 Agent 判断

模型只用于需要语义或开放判断的环节：

- Query 是否有购物意图。
- 候选词与 Query 意图之间的关系。
- 无结果根因及仍需补充查询的信息。
- 图谱修复建议、证据、预期影响和风险判断。

Agent 不直接调用生产写操作，也不决定最终执行权限。

### 4.4 人工决策

以下情况由运营人员决定：

- 高风险、低置信度或影响范围不明确的动作。
- 自动查询达到上限仍无法形成可靠方案。
- 生产写操作未授权。
- 回滚冲突、部分失败或无法自动补偿。
- 二次复查仍无结果或相关性不合格。

## 5. 业务流程

### 5.1 抽取与初筛

系统将不同品牌数据归一为统一业务信息，并过滤：

- 品牌配置排除词。
- 明确测试、纯数字或品牌数据口径规定的无效 Query。
- 仍在有效期内且条件未显著变化的“不处理”记录。
- 重复或已在治理中的任务。

数据源失败或字段不足时记录失败，不以 0 或空结果伪装正常抽取。

### 5.2 购物意图判断

系统判断 Query 是否具有购物意图。兑换、积分、抽奖、门店、优惠券、租赁或回收等非购物场景可进入“不处理”。

“不处理”必须保存原因和有效期。有效期到期、流量明显变化或人工改回待处理时，应重新判断。

### 5.3 候选词与图谱上下文

系统生成候选词语，并查询候选标签是否存在、维度、上下游、同义、从属和互斥等关系。

候选词只用于诊断，不直接等同于最终图谱动作。

### 5.4 根因诊断与补充查询

Agent 判断：

- 新概念或合成词缺失。
- 同义、从属或标签层级关系缺失。
- 错别字、谐音或表达变体未覆盖。
- 既有标签或关系错误。
- 当前证据不足，需要继续查询。
- 不适合自动处理，应转人工。

补充查询轮次、重复意图拦截和停止条件由配置控制。超过上限仍无法形成方案时转人工。

### 5.5 动作计划与执行模式

可能的业务动作包括：

- 新增或更新标签。
- 拉黑或取消拉黑标签。
- 新增、更新或删除标签关系。
- 重新打标签。
- 二次复查。

每个动作必须说明目标、依据、影响范围、风险、预期效果和回滚要求。

最终模式按检查项、工具、风险、权限和环境共同决定：禁止执行、等待人工确认或允许自动执行。当前默认值属于配置，不是永久业务规则。

### 5.6 串行动作、暂停与继续

同一 Query 的多个写动作按计划顺序串行执行：

- 每完成一项即记录真实结果。
- 暂停请求在当前动作完成后生效，不启动下一项。
- 继续时从下一项未完成且仍可执行的动作开始。
- 页面刷新、重复点击或任务恢复不得重复成功动作。
- 某项失败时根据动作依赖决定停止后续动作、重试或转人工。

### 5.7 重新打标签

同品牌成功图谱变更按品牌聚合，在配置的冷却条件满足后统一重新打标签。

- 没有成功图谱变更时不触发。
- 冷却期间的新变更合并到待执行窗口。
- 调用失败时保留待重试或人工状态，不进入二次复查。

### 5.8 二次复查

重新打标签完成并达到配置的等待条件后，系统重新查询该 Query：

- 有召回且相关性合格：治理完成。
- 有召回但相关性不合格：转人工或再次诊断。
- 仍无结果：转人工。
- 查询失败：待重试或失败，不默认成功。

复查必须保留结果数量、商品摘要和判断依据；系统复查不应污染真实用户搜索统计。

## 6. 图谱动作业务规则

### 6.1 同义关系

- 只有语义等价且不存在等价关系时才可新增。
- 关系方向和标签角色必须符合知识图谱业务约束。

### 6.2 从属关系

- 只有明确的上下位关系时才可新增。
- 新增前必须确认关系不存在，避免形成重复或冲突层级。

### 6.3 新标签与合成词

- 新概念必须有购物价值且图谱中不存在等价标签。
- 需要明确标签维度、是否根标签和组合语义。
- 新增后必须经过重新打标签和二次复查。

### 6.4 修改与删除

- 仅在既有标签或关系明确错误、影响召回时提出。
- 删除、关系方向变化和基础属性修改属于高风险业务动作。
- 高风险动作必须有完整执行前证据、人工或配置授权及可行回滚方案。

知识图谱请求字段和接口约束见 `docs/API.md`。

## 7. 回滚

### 7.1 触发范围

运营人员可按单个 Query、批次或品牌日期范围回滚已成功动作。

### 7.2 业务规则

- 回滚按原动作逆序执行补偿。
- 只回滚已成功且尚未回滚的动作。
- 回滚前检查目标对象是否被其他批次修改。
- 存在冲突、目标不存在或无法自动补偿时转人工。
- 部分回滚失败需明确成功与失败对象，不得标记全部成功。
- 回滚完成后仍需重新打标签和二次复查。

回滚只能恢复本系统掌握的执行前状态，不承诺覆盖执行期间所有外部修改。

## 8. 状态变化

典型状态流转：

```text
待处理
-> 不处理 / 待补充信息 / 待执行图谱修复 / 待人工调整
-> 图谱修复执行中 <-> 图谱修复已暂停
-> 已执行待重打标签 / 待重打标签冷却
-> 已重打标签待复查
-> 已完成 / 待人工调整 / 治理失败
```

已成功动作可进入回滚流程，回滚结果为已回滚、部分回滚失败或待人工处理。统一状态映射以 `docs/prd/统一状态与动作契约.md` 为准。

### 8.1 专项阶段到统一状态映射

| 无结果词专项阶段 | 统一任务状态 | 统一检查项状态 | 统一动作状态 / 说明 |
| --- | --- | --- | --- |
| 待处理 | `pending` | `not_started` | 尚无动作 |
| 不处理 | `completed` | `not_applicable` | 不创建动作；必须记录非购物意图或业务排除依据 |
| 待补充信息 | `running` 或 `manual_required` | `data_insufficient` | 自动查询仍可继续时为 `running`，需人工补充时为 `manual_required` |
| 待执行图谱修复 | `running` 或 `manual_required` | `action_pending` | 自动门禁通过时动作 `approved`；需人审时 `waiting_human_approval` |
| 图谱修复执行中 | `running` | `action_pending` | 当前动作 `executing` |
| 图谱修复已暂停 | `manual_required` | `action_pending` | 未执行动作保持原审批状态，已成功动作不得回退 |
| 已执行待重打标签 / 冷却 | `running` | `verifying` | 图谱动作 `executed`，等待重打标签和结果验证，不得提前标记 `verified` |
| 已重打标签待复查 | `running` | `verifying` | 验证进入 `verifying` |
| 已完成 | `completed` | `resolved` | 相关动作 `verified`，最终结论可为 `healthy` |
| 待人工调整 | `manual_required` | `unresolved` 或 `data_insufficient` | 根据已有证据区分仍有问题或数据不足 |
| 已回滚 | `manual_required` | `unresolved` | 原动作 `rolled_back`；Query 仍需复查或人工确认，不因回滚自动视为健康 |
| 治理失败 | `failed` | `check_failed` 或 `unresolved` | 动作为 `execution_failed`、`verification_failed` 或 `rollback_failed` |

映射约束：

- 专项中文阶段只是业务视图，不得替代统一 task/check/action 状态。
- 写操作成功只能进入 `executed`，二次复查通过后才可进入 `verified` / `resolved`。
- “不处理”必须有明确 `not_applicable` 依据，不能用于隐藏检查失败。
- 已回滚只说明外部动作已补偿，不说明无结果问题已解决。

## 9. 异常与恢复

- 配置缺失：停止依赖该配置的自动流程；执行模式缺失时禁止自动写入。
- 数据源失败：保留失败原因并重试或转人工，不创建伪正常任务。
- Agent 失败：按配置重试；没有可靠结论时转人工。
- 查询失败：可重试，不推进到无证据写操作。
- 写操作失败：记录实际结果；状态未知时先核查，不直接重放。
- 超过查询、重试、成本或耗时上限：停止自动治理并转人工或失败。
- 中断恢复：从最近可验证状态继续，已成功动作、已完成查询和冷却进度不重复。
- 并发冲突：同一 Query 只允许一个执行实例；治理与回滚不能并发修改同一对象。

## 10. 展示要求

运营人员应能查看：

- Query、来源指标、当前状态和“不处理”原因。
- Agent 结论、证据、风险和计划动作。
- 每个动作的等待、执行、失败、暂停和回滚结果。
- 执行前后摘要及无法自动回滚的原因。
- 重新打标签和二次复查结果。
- 可执行的开始、暂停、继续、人工处理和回滚操作。

## 11. 验收标准

1. **PRD-10-AC-01**：已接入品牌能按统一口径建立无结果 Query 任务，未接入品牌不会误入自动治理。
2. **PRD-10-AC-02**：非购物意图可进入有有效期的“不处理”状态，并能在条件变化后重新判断。
3. **PRD-10-AC-03**：Agent 只生成判断、查询意图和动作建议，不直接执行生产写操作。
4. **PRD-10-AC-04**：所有图谱动作经过权限、风险、环境、审计、幂等和回滚门禁。
5. **PRD-10-AC-05**：同一 Query 的动作可串行执行、暂停、继续并在恢复后保持进度。
6. **PRD-10-AC-06**：成功变更按品牌聚合重新打标签，之后执行二次复查。
7. **PRD-10-AC-07**：二次复查失败、图谱写入失败和回滚冲突均有明确人工收口。
8. **PRD-10-AC-08**：重复触发、中断恢复和重复点击不会重复已成功动作。
9. **PRD-10-AC-09**：运营人员能从任务记录还原诊断、动作、验证和回滚全过程。
