# 召回结果检查

## 1. 规则

- 召回检查只使用工程化规则判断无结果、少结果和结果数量异常下降。
- 规则使用当前结果数量、前一日同品牌同 Query 的持久化结果数量和品牌配置阈值。只对比紧邻前一天，不计算近 7 日平均值。
- 前一日结果数量缺失时不判断结果数量骤降，也不向页面展示“历史样本不足”；当前数量达到内部数量基线时直接按数量充足处理。
- 发现异常时投递 KG Agent 异步任务，保存品牌、Query、触发来源和证据。
- 异步任务不阻塞主链、不回流；失败只记录异常说明。

## 2. 展示

执行概览的结果数量卡片直接展示持久化结论；详情展示本次结果数量、往期召回数和对比结果，不重复展示顶部数量摘要，也不向用户暴露内部数量阈值。

需要 KG Agent 治理且方案已生成时，详情在执行结果下方逐条展示标签增改和标签关系增改删策略。标签关系只展示“同义”或“从属”；涉及标签逐条展示 Mixed 实时召回数量，待新增标签展示“待创建”。KG 任务生成状态不写入结果数量卡片结论。

## 3. 相关文档

完整规则以[Query 治理重构计划](../Query%20治理重构计划.md)第 4.4 节为准。

## 4. 验收场景

- Given 结果数量达到异常规则，When 召回检查完成，Then 生成 KG Agent 异步任务且不阻塞后续节点。
- Given 前一日同 Query 有持久化结果，When 当前数量相对前一日下降超过配置比例，Then 结论说明本次与前一日召回数量并交由 KG Agent 生成治理策略。
- Given 前一日结果缺失且当前数量充足，When 召回检查完成，Then 结论为“本次召回 X 件，数量充足，无需调整”，不展示历史样本不足。

## 5. 骤降原因前置核验

投递骤降 KG 任务前按 PRD-12 执行商品身份对比和批量上下架/Query 黑名单检查。完整证据显示全部消失商品已下架或拉黑时，记录正常消失及数量，不进入骤降治理。未解释商品最多取 10 件补齐详情提供模型；全部商品的状态检查不受 10 件限制。旧 Top N 快照不能证明全量消失，状态未知不能自动判上架或下架；证据缺失保留待复核，不以搜索首页差集代替消失集合。
