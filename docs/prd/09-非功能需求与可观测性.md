# 非功能需求与可观测性

## 1. 稳定性

- 单品牌、单 Query 或单节点异常不阻塞其他对象和后续节点。
- 状态、动作、回读、错误说明和耗时及时持久化；中断可从第一个未完成节点继续。
- 外部服务超时、图片失败和模型异常按节点规则记录，不以默认健康掩盖。

## 2. 可观测性

按批次、Query、节点和动作记录执行状态、耗时、Token、模型、错误和回读结果；模型调用同时关联 Langfuse Trace。Langfuse 上报失败不得影响主链。

Query 与批次耗时必须分开解释：批次墙钟和共享批次模型时间不计入每个 Query 的独立处理时间。页面和只读 API 应同时展示端到端墙钟、节点墙钟累计、独立处理时间及相关性轮次、动作和复检耗时，并对 Query 端到端与独立处理时间提供平均、P50、P95。无法从持久化证据可靠计算的模型调用、重试、图片和并发指标必须返回空值，不得估算或伪造。

相关性 benchmark 的标签采用三态口径：合成 badcase 为已知负样本，带有明确人工 gold label 的样本才参与正常商品误判率；其余非 badcase 仅作为未审核样本，模型判为不相关时单独列为待人工复核候选，不得直接计入误判率。

## 3. 性能与边界

并发、超时、重试、批量大小和断码巡检周期均可配置。每个节点按实际调用统计资源消耗，不设置 Planner round 或健康评分指标。

## 4. 验收场景

- Given Langfuse 不可用，When 模型调用完成，Then 主链仍按业务结果继续，观测异常单独记录。
